## 1. 集計ルール

### 対象

- Auto Layout の padding
- Item spacing / gap
- Web実装で `padding` / `margin` / `gap` に相当する余白

### 対象外

- 固定 width / height
- アイコン・画像サイズ
- font-size / line-height / letter-spacing
- border-radius / border-width
- 色・影
- 絶対配置された装飾の位置調整（`Glow pink` など）

### 件数の数え方

- 同じコンポーネントを複数画面で再利用していても、コンポーネント定義は1件として数える
- 画面直下のフレームやセクションは、その都度1件として数える
- 同じノードでも、`px` と `py` のように方向が違う指定は別々に数える
- node ID と指定方向で重複を除外する
- px値は丸めず、Figmaから読み取った値をそのまま記録する

表中の方向表記:

| 表記 | 意味 |
| --- | --- |
| `p` | 上下左右すべてのpadding |
| `px` / `py` | 左右 / 上下のpadding |
| `pt` / `pr` / `pb` / `pl` | 上 / 右 / 下 / 左のpadding |
| `gap` | Auto Layout内の要素間隔 |

## 4. 救済問題（Repechage）の扱い

**2026-08-20 決定: 実装対象外。v2でも採用しない。**

理由: `dev_policy/画面・要件確定_policy.md` W5（2026-07-22 確定）で「敗者復活は**アプリ運用しない**（会場 + Google Form + 紙で人力）」と決まっており、`docs/実装要件/画面・要件.md` の「アプリでやらないこと」にも同内容がある。API仕様書・バックエンド実装要件にも敗者復活の記述は無い。**仕様書に完全準拠する。**

Figma の `Mobile/Screen/Repechage/*` `Display/Screen/Repechage/*` は仕様に無い画面であり、**実装対象として扱わない**。

## 6. Display固有画面と除外値

### 救済問題（Repechage）

**2026-08-20 決定: 実装対象外。v2でも採用しない。**（→ §4 に理由と集計への影響）

今回の集計には `Display/Screen/Repechage/*` を含めている。除外すると `120px` と `160px` が消える。

✅ **再集計後の Display 本体は 22種類 / 291件。** 23種類ではなく22種類だったのは、`80px` が救済問題ではなく早押し（下記）に属していたため。

### 早押し問題（Buzzer）

**2026-08-20 決定: フェーズ2用として保留。v1 の整理対象から外すが、削除もしない。**

理由: `docs/実装要件/API仕様書.md` 冒頭で「早押しは **v1未実装・フェーズ2**。仕様上の形だけ先に確保」と決まっており、`docs/実装要件/バックエンド実装要件.md` では v1 の投入バリデーションで `type=hayaoshi` を明示的に弾く。**仕様どおりであり、Figma と矛盾していない**（フェーズ2用に先に描いてあるだけ）。救済問題（§4）とは性質が異なる。

- `80px` は Display では早押し問題だけで使用されている。✅ 再集計で早押しに分類され、Display 本体からは消えた（早押し別枠は計34件）。ただし **Mobile の終了画面にも `80px` があるため、3画面合計の34種類には残っている**
- ⚠️ 混同注意: 「問題文の**順次表示**」（`textSegments` / `revealedSegments` / `advance-text`）は**全type共通の仕組みで v1 実装対象**。v1 で作らないのは `type=hayaoshi` 専用のレイアウトの方

### 絶対配置の装飾

Ready画面の `Glow pink` には `190px` の位置調整用marginがあるが、絶対配置された装飾の座標に相当するため、スペーシング集計から除外した。

### 既存のFigma Variables

`Screens/Display` では、スペーシングに割り当てられたFigma Variablesは確認できなかった。表の25種類は、現在の具体的なpx指定を記録している。

## 10. 端数の扱いの決定（2026-08-20）

**数字はすべて再集計後（救済問題を除外した本体のみ）のもの。**

### 判断軸: Tailwind 標準スケールに収まるか

Tailwind の既定スペーシングスケールには `0.5 / 1.5 / 2.5 / 3.5` が含まれるが、**`.25` `.75` は存在しない**。

| px | ÷4 の結果 | Tailwind 標準 |
| --- | --- | :---: |
| 偶数 | `.5` 刻み | ✅ ある |
| 奇数 | `.25` / `.75` 刻み | ❌ 無い |

**「4px グリッドに揃える」ことはしない。2の倍数まで許容する。** 端数の多くは光学調整であり、丸めるとデザイナーの意図を壊すため。そして偶数であれば Tailwind 標準の形に収まる。

### 全体像

| 分類 | 種類 | 件数 | 決定 |
| --- | ---: | ---: | --- |
| 4px グリッド上 | 20 | 724 | そのまま |
| グリッド外・**偶数** | 10 | 129 | **据え置き**（`p-6.5` などは Tailwind 標準の形） |
| グリッド外・**奇数** | 4 | 20 | 下記 |
| **合計** | **34** | **873** | |

### グリッド外の内訳（14種 / 149件）

`画面` 列は M=Mobile / D=Display / a=admin。

| px | Tailwind | 件数 | 画面 | 使用箇所 | 決定 |
| ---: | --- | ---: | --- | --- | --- |
| 10px | `p-2.5` | 83 | MDa | ロゴ、ヘッダー、ボタン、プレビュー | **残す。**3画面で多用され、Figma に既存 Variable `space/2-5` がある正規の段 |
| 18px | `p-4.5` | 10 | MDa | ヘッダー、イベント名、パスワード入力 | **残す。**3画面すべてで使用 |
| 2px | `p-0.5` | 14 | M-a | 正答表示、問題ID・問題文セル | 据え置き。4px にすると2倍になり変化が大きすぎる |

**Figma に加える値変更は `19px` → `20px` の9件だけ。** before/after の確認も1箇所で済む。

### 奇数 px は例外なくすべて据え置く

「1件しかないから寄せる」といった**件数ベースの例外を作らない**。理由は2つ。

1. **ルールに例外があると運用できない。** 「奇数はスケール外の値として意図的に残す」と決めた以上、`13px` だけ別扱いにすると、次に奇数が出たときの判断基準が失われる
2. **寄せるには Figma を書き換える必要がある。** 据え置けば Figma に触らずに済む。見た目が変わるリスクを、整理の見栄えのためだけに取らない

### A〜D ラベルの3点セット

Display の4択ラベルは `pl=26 / pr=29 / pb=23` で、**左右が非対称**（26 ≠ 29）。これは A〜D の文字を箱の中で**光学的に中央へ寄せる**ための調整であり、3つで1つの意味を持つ。

`26px` を据え置くと決めた以上、`29px` だけを `28px` に丸めると非対称が崩れて文字がずれる。**3つセットで残す。**

### コード側の書き方

奇数 px は**トークンを作らない。任意値で書く。**

```tsx
// features/monitor/parts/ChoiceLabel.tsx
// A〜Dラベル。左右非対称なのは文字を光学的に中央へ寄せるため（Figma準拠）
<span className="pl-[26px] pr-[29px] pb-[23px]">{label}</span>
```

admin のログインボタンも同じ（`py-[13px]`）。

理由:

- `--spacing-label-pb: 23px` のようなトークンは**名前を付けられない**。`23px` は「A〜Dラベルの下 padding」でしかなく、再利用される「意味のまとまり」が存在しない。マジックナンバーを改名しただけになる
- `p-5.75` は「スケール上の値のつもりで間違えている」ように読めるが、`pb-[23px]` は「意図的にスケールから外した」と読める。**出力される CSS は同じで、読み手に伝わる意味だけが違う**
- Figma 上では5インスタンスあるが、**コードでは1コンポーネントに閉じる**。呼ぶ側は `<ChoiceLabel label="A" />` としか書かない。「1箇所を直せば全部変わる」というトークンの役割は、コンポーネント化で達成される

### Figma 側であえてバインドしない

奇数 px は Variables にバインドしない（→ [`FigmaスペーシングVariables設定指示書.md`](./FigmaスペーシングVariables設定指示書.md) §2.4）。これは保留ではなく積極的な選択で、**バインドの有無そのものが「スケール内／外」の印**になる。

| Dev Mode の表示 | 意味 |
| --- | --- |
| `space/6` | スケール上の値。他と揃える対象 |
| `23px` | 生の数値のまま = 意図的に外した値 |

## 11. `--spacing` を上書きしない決定（2026-08-20）

### 決定

**`frontend/src/index.css` では `--spacing` を上書きしない。Tailwind 既定の `0.25rem` のまま使う。**

```css
@import 'tailwindcss';
```

一度 `@theme { --spacing: 4px; }` を入れたが、**撤回した**。

### 撤回の理由: 上書きするメリットが存在しなかった

上書きの目的は「Figma の px と Tailwind のクラス番号を1対1で対応させること」だった。しかし**その対応は既定のままで最初から成立していた。**

Tailwind v4 が生成する CSS は、上書きの有無にかかわらず完全に同一。

```
既定（--spacing: 0.25rem）        上書き（--spacing: 4px）
.p-4 { padding: calc(var(--spacing) * 4) }   ← まったく同じ
```

そして既定値 `0.25rem` は、標準の root font-size（16px）では **4px**。

| クラス | 既定（rem） | 上書き（px） |
| --- | --- | --- |
| `p-1` | 0.25rem = **4px** | **4px** |
| `p-2.5` | 0.625rem = **10px** | **10px** |
| `p-4` | 1rem = **16px** | **16px** |
| `p-12` | 3rem = **48px** | **48px** |

**`Tailwind クラス番号 = Figma の px ÷ 4` は、何もしなくても成立する。**

### 一方、デメリットは実在した

ブラウザの文字サイズ設定を大きくしたとき:

| | 文字 | 余白 | 結果 |
| --- | --- | --- | --- |
| rem（既定） | 拡大 | **一緒に拡大** | レイアウトの比率が保たれる |
| px（上書き） | 拡大 | **固定のまま** | 文字だけ膨らんで詰まる・はみ出す |

影響する操作:

| 操作 | 影響 |
| --- | --- |
| ピンチズーム / `Ctrl` + `+` | **どちらでも同じ**（全体が拡大するので差が出ない） |
| **Android Chrome の文字サイズ設定** | px だと余白が追随しない |
| デスクトップの既定フォントサイズ変更 | 同上 |
| Firefox「文字のみズーム」 | 同上 |
| iOS Safari の文字サイズ | ほぼ影響なし（既定では Web の root font-size を変えない） |

参加者は約200人が自分のスマホで見る。**文字を大きく設定している人の画面で、問題文が膨らんで選択肢からはみ出す可能性がある。**

また `--spacing` は `p-*` `m-*` `gap-*` だけでなく **`w-*` `h-*` `inset-*` にも効く**ため、影響範囲は余白だけではない。

### 残る論点（採用しなかった側の言い分）

奇数 px を `pb-[23px]` のようにハードコードすると決めた（→ §10）ので、**そこだけ文字拡大に追随しない**。全体が rem だと2種類が混在する。

ただし対象は A〜Dラベルなど11件で、**光学的な微調整は本来グリフの見た目に対する補正**なので、混在していても不自然ではない。撤回を止める理由にはならないと判断した。

### この決定が影響しないもの

| 対象 | 影響 |
| --- | --- |
| `px ÷ 4 = クラス番号` のルール | **なし。**既定のままで成立する |
| Figma の `space/N` Variables | **なし。**Figma は元々 px しか持たない |
| §10 の端数の扱い | **なし** |
| 3画面の実装手順書 | **なし。**÷4 のルールしか書いていない |
