# 管理者画面(#20) Figma・イシュー突合

Figma の管理者画面デザイン(`figma-design/Main Content.png`)と、分割イシュー #106〜#111 を突き合わせた結果。
**2026-09-11 時点の提案。まだ決定ではない。**

## 0. この作業の原則

ズレが見つかったとき、**どちらかを削って揃えてはいけない。**

- **イシューにあって Figma に無いもの** → 当日の進行に必要な機能なので、**デザインを足す**
- **Figma にあってイシューに無いもの** → デザイン済みの画面が実装されずに終わるので、**イシューを足す**

この2方向のどちらでも、「片方に無いから落とす」は選ばない。管理者画面は当日1人が触る唯一の操作盤で、機能が1つ欠けると進行が止まる。

## 2. ズレの内訳

### A. 出題中の問題パネル(#107)

| ズレ | 向き | 対応 |
| --- | --- | --- |
| バッジが「回答受付中」、`labels.ts` は「出題中」 | 文言の二重管理 | どちらかに寄せ、`labels.ts` 一箇所で持つ |
| バッジが `question` の1状態しか無い | Figma に不足 | 残り3つ(待機中・正答表示中・終了)の文言と色を決める |
| 「第何問か」(`askedCount`)が無い | Figma に不足 | ID とは別物。当日司会と読み合わせるのはこちら |
| 問題文の公開状況(`revealedSegments`)が無い | Figma に不足 | 未公開部分に印が要る。裏方が先に読み上げると事故る |

`制限時間 30秒` は `timeLimitSec` をそのまま出すだけでよい。カウントダウンは操作パネル側(§2-E)。
`timeLimitSec` は `null` になり得るので、そのときの表示を決めること。

### B. 画面プレビュー(#111)

**Figma はモニタとスマホの2枚を並べているが、イシューはモニタ1枚しか書いていない。**

スマホは参加者の手元に映るものなので、裏方が確認したい対象としてはモニタと同格。デザイン側が正しい。
イシューに「スマホプレビュー」を足す。ただし実装の手間は2倍ではなく、**削り込みの規則が2種類になる**のが本体。

- モニタ向け: `AdminState` → `MonitorState` 相当に削る(#111 に既に表がある)
- スマホ向け: `AdminState` → `ViewerState` 相当に削る(API仕様書 §2.2)

どちらも `revealedSegments` で `textSegments` を切り詰め、`answer` phase 以外では正答・解説を渡さない、という点は同じ。

### C. 問題リスト(#109)

Figma の列は 選択ラジオ / ID / 問題文 / 形式バッジ / 難易度バッジ。**イシューが要求している「出題済みか」の表示が無い。**

当日「これもう出したっけ?」が一目で分からないと事故るので、`asked` の列かバッジを Figma に足す。
`hasImage`(画像あり)も同様にイシュー側にあってデザインに無い。こちらはバッジ1つで足りる。

選択がラジオボタン(単一選択)になっているのは、#108 の「選んで出す」方式と合っている。ここは問題ない。

> ⚠️ 形式バッジの表記が `labels.ts` と違う。Figma は「有無」、`labels.ts` は「あるなし」。どちらかに寄せる。

### D. 選択中の問題(**新規イシューが要る**)

**Figma のこのパネルは、どのイシューにも割り当てられていない。** そして実装は見た目ほど軽くない。

問題リストが返す `QuestionListItem` には `textPreview` しか無く、**選択肢も正答も入っていない**(API仕様書 §4.1)。
Figma のこのパネルは選択肢A〜Dと正答を出しているので、`GET /api/admin/questions/:id`(§4.2)を別途叩く必要がある。

そして **§4.2 のサーバー実装(#79)はまだ OPEN。** 依存関係が増えるので、#109 に混ぜず独立したイシューにする。

### E. 操作パネル(#108)

双方向にズレている。

**Figma に足すもの(機能として必須)**

| 足すもの | なぜ必要か |
| --- | --- |
| 「次を表示」ボタン | `advance-text`。問題文を区切りごとに公開する操作。これが無いと `revealedSegments` が進まない |
| 「クイズを終了」ボタン | `reset {"to":"finished"}`。これを押さないと終了画面(アンケートQR)に行けない |
| 秒数の入力欄(既定30・5〜120) | `show-question` の `timeLimitSec`。範囲外は押す前に画面で止める |
| 確認ポップアップ | 「正答を表示」の誤爆防止。**手順書 §6 の最重要要件** |

Figma の「待機画面を表示」は `reset {"to":"waiting"}` に当たる。終了と待機の2種類があることが画面上で区別できる必要がある。

**イシューに足すもの**

Figma の「残り時間 00:30」がどのイシューにも無い。`questionStartedAt` と `timeLimitSec` から各端末が計算する表示で、`lib/useRemainingTime.ts` が既にある。**#108 の操作パネルに含める。**

> #107 のレビュー観点「`serverTime` を毎秒表示する作りにしない」と矛盾しない。禁じているのはサーバーから来た時刻の垂れ流しで、残り時間はクライアント計算。置き場所が #107 ではなく #108 になるだけ。

### F. デザインが無いパネル(#110 / #105)

貼り付け投入(#110)と画像投入(#105)は、Figma に描かれていない。
どちらも当日の保険であり、#110 は GAS 直送が失敗したときの唯一の投入手段。**落とせない。**

実装を止める必要はない。既存パネルの枠・ラベル・ボタンの様式に揃えて実装し、デザインは後から当てる。

### G. 全パネル共通で Figma に無いもの

- **操作が失敗したときのエラー表示**(どの操作に失敗したかが分かる文言)
- **送信中(busy)の見た目**(操作盤全体が無効になっている状態)

どちらも各イシューの受け入れ条件に入っている。共通の見た目を1つ決めて、全パネルで使い回す。

## 3. イシューの書き換え案

### #107(2/6 現在の状況表示)

- 実装対象を「Figma の**出題中の問題パネル + 状態バッジ**」と明記する
- 表示項目を Figma に合わせて追記: ID / 問題形式 / 難易度 / 制限時間 / 問題文 / 選択肢 / 正答
- 「第何問か」と「問題文の公開状況」は **Figma に無いがイシューの受け入れ条件として残す**(§2-A)
- `timeLimitSec` が `null` のときの表示を決める
- 残り時間のカウントダウンは**このイシューに含めない**(#108 へ)

パーツ:

| --- | --- |
| `parts/StatusBadge.tsx` | phase 4状態のバッジ |

### #108(3/6 進行操作)

- ボタンを4つに明記: 次を表示 / 正答を表示 / 待機画面を表示 / クイズを終了
- **残り時間の表示をこのイシューに追加**(§2-E)
- 秒数入力の置き場所を「選択中の問題パネルの出題ボタン横」と決める(Figma に合わせる)
- エラー表示と busy の共通見た目をここで決める(§2-G)

パーツ: `ControlPanel` / `ShowQuestionForm` / `ConfirmDialog` / `RemainingTime` / エラー表示

### #109(4/6 問題一覧)

- 列を Figma に合わせて明記: 選択ラジオ / ID / 問題文 / 形式 / 難易度

- 形式バッジの表記ゆれを解消する

### #111(6/6 プレビュー)

- **スマホプレビューを追加**し、タイトルを「モニタ・スマホのプレビュー」に変える(§2-B)

- レビュー観点の「未公開セグメントが出ていない」「正答が出ていない」を**両方に**適用する

### 新規(選択中の問題パネル)

- Figma の「選択中の問題」パネルを実装する
- `GET /api/admin/questions/:id`(§4.2)を叩く
- **依存: #79**(サーバー未実装)。それまでは仮データで先行してよい
- 依存: #109(選択元)、#108(出題ボタンの動作)

### #110 / #105

イシューの書き換えは不要。**デザイン側の宿題として残す。**

## 4. 決定(2026-09-12)

1. **状態バッジは phase ではなく「会場に出ている状態」**。モニタ・スマホが既に実装している3状態(回答受付中 / 回答締切 / 正解発表)と文言・色トークンを揃える。`waiting` / `finished` はバッジを出さず、パネル本体に `phaseLabel` を出す。`labels.ts` の `PHASE_LABEL` は用途が違うので残す
2. **問題形式は Figma に合わせる**。`labels.ts` の `arunashi` を「あるなし」から**「有無」**に変える
3. **「選択中の問題」は新規イシュー**にする(#109 に混ぜない)
4. **#79 は PM が自分で実装する**。→ [`問題詳細API(#79)実装手順書.md`](./問題詳細API\(#79\)実装手順書.md)
5. Figma への追加項目は「デザイン側の宿題」として一覧化した。→ [`管理者画面(#20)イシュー改訂案.md`](./管理者画面\(#20\)イシュー改訂案.md) §7
