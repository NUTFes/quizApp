## 1. 「Bearer の公式ドキュメント」を読む必要はない

Bearer は製品でもライブラリでもなく、**HTTP ヘッダの書き方の決まりごと**です。仕様（RFC 6750）を読んでも、得るものは実質この1行しかない。

```
Authorization: Bearer dev-admin-token
```

`Bearer` は「持参人払い」という意味。小切手と同じで、**この文字列を持っている人が誰であっても通す**。ID もパスワードも聞かない。

この性質が、そのまま運用ルールの理由になっている。

| Bearer の性質 | だからこうする |
| --- | --- |
| 持っている人なら誰でも通る | 漏れたら終わり → 本番トークンは当日発行・終了後に破棄（使い捨て） |
| 文字列そのものが鍵 | **ログに出さない**（出すなら `len(token)` だけ） |
| URLに入れると履歴・アクセスログに残る | `?token=` は受け付けない。ヘッダのみ（SSEだけ例外・§5） |

**つまり Bearer 側に学ぶことは無い。** 実装するのは「文字列を比べて、違ったら止める」だけ。

**本当に読むべきは Gin のミドルウェア**です。

- https://gin-gonic.com/en/docs/examples/custom-middleware/
- https://gin-gonic.com/en/docs/examples/using-middleware/

## 2. Gin の最小知識（これだけで足りる）

### 2-1. ハンドラは全部この形

```go
func(c *gin.Context)
```

`*gin.Context` が「1回のリクエストとレスポンスの入れ物」。使うのは次の4つだけ。

| | 何をするか |
| --- | --- |
| `c.GetHeader("Authorization")` | リクエストヘッダを読む。無ければ空文字 `""` |
| `c.JSON(200, gin.H{"ok": true})` | JSON を返す |
| `c.Next()` | 次のハンドラへ進む |
| `c.Abort()` | ここで打ち切る。**以降のハンドラは実行されない** |

### 2-2. ミドルウェアは「ハンドラと同じ形の関数」

特別な型は無い。**置かれる位置が違うだけ**です。

```
リクエスト ──▶ [ミドルウェア] ──▶ [本来のハンドラ] ──▶ レスポンス
                     │
                     └─ ここで止めれば、本来のハンドラは動かない
```

### 2-3. `platform.RespondError` は自分で Abort する

このプロジェクトには共通のエラー返却があります（[`platform/response.go`](../backend/internal/platform/response.go)）。

```go
platform.RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "トークンが違います")
```

**中で `c.AbortWithStatusJSON` を呼んでいるので、自分で `c.Abort()` を書く必要はありません。** `RespondError` して `return` すれば止まります。

`c.JSON(...)` を自分で組み立てないこと。エラーの形は全API共通の契約です（API仕様書 §0）。

### 2-4. ルータグループ

**「このパスの下は全部このミドルウェアを通す」**をまとめて指定する仕組み。

```go
g := r.Group("/api/admin", platform.RequireToken(adminToken))
g.GET("/verify", verify)      // → GET /api/admin/verify
g.POST("/reset", reset)       // → POST /api/admin/reset
```

`/api/admin/**` に後から何本エンドポイントを足しても、**認証は自動的に付きます。** 1本ずつ書かないこと（付け忘れが必ず起きる）。

## 3. 何を作るのか

| ファイル | 中身 |
| --- | --- |
| `backend/internal/platform/auth.go`（新規） | `RequireToken` |
| `backend/internal/admin/admin.go`（新規） | `RegisterRoutes` と `verify` |
| `backend/cmd/server/main.go` | 環境変数を読んで1行足す |
| `docker-compose.yml` | 環境変数の修正 |

### なぜ認証が `platform` で、verify が `admin` なのか

**判断基準は「誰が使うか」であって、話題が管理者かどうかではありません。**

| | 認証 | verify |
| --- | --- | --- |
| URLを持つか | 持たない（手前で動くだけ） | 持つ（`/api/admin/verify`） |
| ドメイン知識を含むか | 含まない（文字列比較のみ） | 含む（管理者画面の起動時確認） |
| admin機能を消したら消えるか | **消えない** | 消える |

決め手は最後の行。**`IMPORT_TOKEN` は問題投入（将来の `sheetsync`）でも使う。** 認証を `admin` に置くと `sheetsync` が `admin` を import することになり、`フォルダ構成_policy.md` のルール2に反します。

**ファイル名は `auth.go`、`middleware.go` ではない。** 「仕組み」ではなく「役割」で名前を付ける。`middleware.go` は入れ物の名前なので、無関係なコードを呼び寄せて、そのうち誰も開きたくないファイルになる。既存の `response.go`（エラー応答）・`router.go`（ルータ組み立て）も同じ規則です。

## 4. 実装の順番

### Step 1: 何も見ずに必ず通すミドルウェア（配線だけ）

**まず認証を書かない。** 「ミドルウェアがちゃんと呼ばれているか」だけを確かめます。

```go
// backend/internal/platform/auth.go
package platform

import (
	"log"

	"github.com/gin-gonic/gin"
)

// RequireToken は Authorization ヘッダのトークンを照合するミドルウェア。
func RequireToken() gin.HandlerFunc {
	return func(c *gin.Context) {
		log.Println("RequireToken が呼ばれた")
		c.Next()
	}
}
```

```go
// backend/internal/admin/admin.go
package admin

import (
	"net/http"

	"github.com/gin-gonic/gin"

	"github.com/naoto-anzai/quizApp/backend/internal/platform"
)

// RegisterRoutes は管理者APIを登録する。
func RegisterRoutes(r *gin.Engine) {
	g := r.Group("/api/admin", platform.RequireToken())
	g.GET("/verify", verify)
}

// verify はトークンが有効かを確かめるだけのAPI(§4.3)。
// login も logout も無い。管理者画面が起動時に1回叩く。
func verify(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"ok": true})
}
```

`main.go` の `NewRouter` に1行足す。

```go
r := platform.NewRouter(
	admin.RegisterRoutes,
	registerEvents,
)
```

> **なぜ `RequireToken()` が「関数を返す関数」なのか**
> Gin のミドルウェアは `gin.HandlerFunc`（＝`func(*gin.Context)`）でなければならない。でも後で「どのトークンを許すか」を外から渡したい。**外側の関数で設定を受け取り、内側で `gin.HandlerFunc` を返す**とそれができる。Go でよく出る形なので、ここで慣れておくとよい。

**✅ 動作確認:**

```bash
curl -i http://localhost:3000/api/admin/verify
```

`200` と `{"ok":true}` が返り、`docker compose logs backend` に `RequireToken が呼ばれた` が出る。

**⚠️ まだ足りない:** 誰でも通る。**今これは認証ではなくただのログ出力です。**

### Step 2: 固定の文字列と比べる

まず一番素朴な形。ヘッダ全体を丸ごと比較します。

```go
func RequireToken() gin.HandlerFunc {
	return func(c *gin.Context) {
		if c.GetHeader("Authorization") != "Bearer dev-admin-token" {
			RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "トークンが違います")
			return
		}
		c.Next()
	}
}
```

import に `net/http` を足し、`log` は消す。

> **`message` に何を書くか。** `message` は開発者向けのデバッグ文言で、画面には出ません（API仕様書 §0）。フロントが分岐に使うのは `code` の方。**ただしトークンの中身は絶対に書かないこと。** エラーレスポンスもログに残ります。

**✅ 動作確認:**

```bash
curl -i http://localhost:3000/api/admin/verify                                    # 401
curl -i -H "Authorization: Bearer dev-admin-token" http://localhost:3000/api/admin/verify   # 200
```

**⚠️ まだ足りない:** トークンがソースコードに直書きされている。**公開リポジトリなので、本番の値をここに書くことは絶対にできません。**

---

### Step 3: `Bearer ` を正しく剥がす

ヘッダ丸ごとの比較には穴があります。**`Bearer` を付け忘れたリクエストと、トークンが違うリクエストを区別できない。** それにこの先トークンが複数になると、比較のたびに `"Bearer " + token` を組み立てることになる。

**接頭辞を剥がして、中身だけを扱う**形に変えます。

```go
const bearerPrefix = "Bearer "

func RequireToken() gin.HandlerFunc {
	return func(c *gin.Context) {
		token, ok := strings.CutPrefix(c.GetHeader("Authorization"), bearerPrefix)
		if !ok || token == "" {
			RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "Authorization ヘッダがありません")
			return
		}
		if token != "dev-admin-token" {
			RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "トークンが違います")
			return
		}
		c.Next()
	}
}
```

`strings.CutPrefix` は「剥がした残り」と「剥がせたかどうか」を返します（Go 1.20以降）。

> **`token == ""` も一緒に弾いておく。** 「空のトークンが、空の環境変数と一致して素通りする」経路を塞ぐためのものです。
>
> ただし正直に言うと、**HTTP 経由でこの条件に入ることはまずありません。** Go の HTTP サーバーはヘッダ値の前後の空白を落とすので、`Authorization: Bearer ` は `"Bearer"` として届き、`CutPrefix` の時点で `ok == false` になります（確認済み）。
>
> それでも書くのは、**この関数が HTTP 以外から呼ばれたときや、前提が変わったときに備えるため**です。空トークン素通りは Step 6 の `valid` フィルタでも塞ぎますが、**認証は1箇所の守りに頼らない。**

**✅ 動作確認:**

```bash
curl -i -H "Authorization: dev-admin-token" http://localhost:3000/api/admin/verify   # 401(Bearerが無い)
curl -i -H "Authorization: Bearer " http://localhost:3000/api/admin/verify           # 401(値が空。curlとGoが末尾の空白を落とすので Bearer 無し扱いになる)
curl -i -H "Authorization: bearer dev-admin-token" http://localhost:3000/api/admin/verify  # 401(小文字)
```

> 小文字の `bearer` を弾くのは仕様上は厳しすぎる（RFC では大文字小文字を区別しない）が、**このアプリのクライアントは自分たちが書くフロントと GAS だけ**なので、厳しいままでよい。緩めると「なぜか通る書き方」が増えて事故のもとになる。

**⚠️ まだ足りない:** まだ直書き。

### Step 4: 環境変数から受け取る

**`RequireToken` の中で `os.Getenv` を呼ばないこと。** 設定を読むのは起動時の1回きりにして、`main.go` に集めます。そうしないと「この関数がどの環境変数に依存しているか」がソース全体に散らばります。

引数で受け取る形に変えます。

```go
func RequireToken(allowed string) gin.HandlerFunc {
	return func(c *gin.Context) {
		token, ok := strings.CutPrefix(c.GetHeader("Authorization"), bearerPrefix)
		if !ok || token == "" {
			RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "Authorization ヘッダがありません")
			return
		}
		if token != allowed {
			RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "トークンが違います")
			return
		}
		c.Next()
	}
}
```

`admin.RegisterRoutes` もトークンを受け取る必要があります。でも `NewRouter` が受け取れるのは `platform.RegisterFunc`（＝`func(*gin.Engine)`）だけ。**Step 1 と同じ「関数を返す関数」の形にします。**

```go
// RegisterRoutes は管理者APIを登録する。
// トークンを外から渡す必要があるので、RegisterFunc を返す形にしている。
func RegisterRoutes(adminToken string) platform.RegisterFunc {
	return func(r *gin.Engine) {
		g := r.Group("/api/admin", platform.RequireToken(adminToken))
		g.GET("/verify", verify)
	}
}
```

`main.go`:

```go
func main() {
	adminToken := os.Getenv("ADMIN_TOKEN")

	r := platform.NewRouter(
		admin.RegisterRoutes(adminToken),
		registerEvents,
	)
	...
}
```

**✅ 動作確認:** `docker-compose.yml` に `ADMIN_TOKEN` を足して（→ Step 7）から Step 3 と同じ curl を流す。

**⚠️ まだ足りない:** **環境変数を設定し忘れると `allowed` が空文字になります。** 空文字のトークンを HTTP で送りつける経路が無いので素通りはしませんが、**代わりに全リクエストが 401 になります。**

これは**気づくのが遅い壊れ方**です。サーバーは正常に起動し、ヘルスチェックも通り、管理画面を開いて初めて「なぜかログインできない」という形で表面化する。しかも原因がトークンの打ち間違いなのか設定漏れなのか、画面からは区別できません。当日これをやると詰みます。

### Step 5: 設定ミスで起動を止める

**サーバーが立ち上がった＝設定は正しい、という状態にします。**

```go
func main() {
	adminToken := os.Getenv("ADMIN_TOKEN")
	if adminToken == "" {
		log.Fatal("ADMIN_TOKEN が設定されていません")
	}
	...
}
```

> **なぜ「全部401」ではなく「起動しない」なのか。** 全部401だと、当日「管理画面にログインできない」という形で初めて気づくことになる。原因がトークンの打ち間違いなのか設定漏れなのかも分からない。**起動時に落ちれば、`docker compose logs` の一番上に理由が出ます。**
>
> なお `RequireToken` 側の空チェック（Step 3）は残しておくこと。**入口と手元の両方で守る。** 将来 `main.go` 以外から呼ばれても安全なようにしておきます。

**✅ 動作確認:**

```bash
docker compose exec backend sh -c 'ADMIN_TOKEN= go run ./cmd/server'
# → ADMIN_TOKEN が設定されていません と出て終了する
```

**⚠️ まだ足りない:** トークンが1つしか渡せない。**問題投入APIは `IMPORT_TOKEN` でも `ADMIN_TOKEN` でも通す**必要があります（バックエンド実装要件 §6）。

### Step 6: 複数のトークンを受け取れるようにする

可変長引数にします。Issue #10 が指定しているシグネチャはこれです。

```go
func RequireToken(allowed ...string) gin.HandlerFunc
```

```go
// RequireToken は Authorization: Bearer の値が allowed のいずれかと一致するリクエストだけを通す。
//
//	admin API      : RequireToken(adminToken)
//	問題投入(§3.5) : RequireToken(adminToken, importToken)
//
// 空文字は許可トークンとして扱わない。環境変数の設定漏れがそのまま
// 「誰でも通る」状態にならないようにするため。
func RequireToken(allowed ...string) gin.HandlerFunc {
	// フィルタは起動時に1回だけ。リクエストのたびにやり直さない。
	valid := make([]string, 0, len(allowed))
	for _, token := range allowed {
		if token != "" {
			valid = append(valid, token)
		}
	}

	return func(c *gin.Context) {
		token, ok := strings.CutPrefix(c.GetHeader("Authorization"), bearerPrefix)
		if !ok || token == "" {
			RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "Authorization ヘッダがありません")
			return
		}

		for _, want := range valid {
			if token == want {
				c.Next()
				return
			}
		}

		RespondError(c, http.StatusUnauthorized, "UNAUTHORIZED", "トークンが違います")
	}
}
```

**`valid` が空なら、ループが1度も回らずに必ず 401 になります。** 「分からなければ拒否する」側に倒れる形です。認証はこの向きに壊れるように書く。

`main.go` で `IMPORT_TOKEN` も読み、問題投入APIにだけ両方を渡す（実際に使うのは #12 以降）。

```go
adminToken := os.Getenv("ADMIN_TOKEN")
importToken := os.Getenv("IMPORT_TOKEN")
```

**✅ 動作確認:** `IMPORT_TOKEN` で `/api/admin/verify` を叩いて **401 になること**。ここが通ってしまうと、GAS のトークンで進行を操作できてしまいます。

**⚠️ まだ足りない:** 比較が `==` のまま。

---

### Step 7: 比較を定数時間にする

Go の `==` による文字列比較は、**違うバイトを見つけた時点で打ち切ります。** つまり「1文字目から違う」より「10文字目まで合っている」ほうがわずかに時間がかかる。この差を大量のリクエストで測ると、トークンを1文字ずつ当てられます（タイミング攻撃）。

```go
import "crypto/subtle"

if subtle.ConstantTimeCompare([]byte(token), []byte(want)) == 1 {
	c.Next()
	return
}
```

`ConstantTimeCompare` は**最後まで必ず比較する**ので、時間差が出ません。一致すると `1`、しなければ `0` を返します。

> **正直に言うと、この対策が効く場面はこのアプリにはほぼ無い。** ネットワークの揺らぎのほうが時間差よりはるかに大きく、当日の来場者にそんな攻撃をする人はいない。**それでも書くのは、1行で済むからです。** 認証コードは「安いなら守っておく」でよく、ここで節約する意味が無い。

**✅ 動作確認:** Step 6 までの curl が全部同じ結果になる。**挙動は何も変わりません。**

**⚠️ まだ足りない:** 環境変数がまだ古い名前のまま。

## 6. 仕様の落とし穴（書く前に読む）

### 🚫 `?token=` を受け付けてはいけない

SSE の管理者チャンネル（§5）**だけ**が例外で、そこは `EventSource` がヘッダを付けられないという技術的制約による妥協です。**それ以外で URL にトークンを載せると、Cloudflare のアクセスログ・ブラウザ履歴・画面共有・スクショに残ります。**

`RequireToken` に `c.Query("token")` を見るコードを足さないこと。SSE 側は #13 で別に扱います。

### 🚫 トークンをログに出さない

```go
log.Printf("token=%s", token)              // ❌ 絶対にやらない
log.Printf("token length=%d", len(token))  // ✅ どうしてもデバッグしたいとき
```

**もし本番トークンをコミットしたりログに出したりしてしまったら、隠さずすぐ PM に言ってください。** トークンを差し替えれば済む話です。黙っているほうが何倍も高くつきます。

### ⚠️ 401 だけを使う。403 は使わない

「ヘッダが無い」も「トークンが違う」も、API仕様書では**どちらも 401 `UNAUTHORIZED`** です（§3.5.3・§4.3）。

403 を使いたくなりますが、**フロントは `code` で分岐する**と決まっており、契約に無いステータスを増やすと管理者画面側が対応できません。増やしたくなったら仕様書を直すのが先。

### ⚠️ 管理者パス `/backstage-0248` は秘密ではない

このパスは公開リポジトリにも PR にも書いてよい。**秘密なのはトークンだけ**です。パスを隠すことをセキュリティとして数えないこと。

### ⚠️ 認証はグループにまとめて掛ける

```go
g := r.Group("/api/admin", platform.RequireToken(adminToken))   // ✅
g.GET("/verify", platform.RequireToken(adminToken), verify)     // ❌ 1本ずつは付け忘れる
```

このあと #11・#12 で管理者APIが増えます。**グループに掛けておけば、後から足したエンドポイントは自動で守られます。**
