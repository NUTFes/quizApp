## 2. 設計の全体像(ここを理解してから書く)

### 2-1. 「状態を持つ場所」と「描くだけの部品」を分ける

#107 で決めた方針を、このIssueでもそのまま守る。

```
OperationPanel.tsx  … 状態を持つ・通信する(ここだけ)
  │   state(SSE) / remainingSec / busy / failure / timeLimitInput
  │
  ├── CurrentStatus     … props を描くだけ(#107)
  ├── ControlPanel      … props を描くだけ(確認ポップアップの開閉だけは自分で持つ)
  │     ├── RemainingTime
  │     └── ConfirmDialog
  ├── ShowQuestionForm  … props を描くだけ
  └── ErrorBanner       … props を描くだけ
```

**なぜ分けるのか。** 部品の中で `fetch` したり `localStorage` のトークンを読んだりすると、`/dev/admin`(通信もトークンも無い場所)で描けなくなる。すると「送信中の見た目」「エラーの見た目」「締切の見た目」を確認するために、毎回サーバーをわざとその状態にしないといけない。

判断に迷ったら「**この部品は `/dev/admin` に props を渡すだけで全状態を並べられるか?**」と自問する。

> 例外として、`ControlPanel` が「確認ポップアップを開いているか」を `useState` で持つのは OK。これは通信と無関係な、画面の中だけの状態だから。

### 2-2. ボタンを押したときの流れ

```
裏方が「次を表示」を押す
  ↓
OperationPanel.run('次を表示', advanceText)
  ├─ busy = true   → 操作盤の全ボタンが押せなくなる
  ├─ failure = null → 前のエラーを消す
  ├─ await advanceText()  … POST /api/admin/advance-text
  │     成功 → 何もしない(state は SSE で届く)
  │     401  → onAuthExpired() でログイン画面へ
  │     失敗 → failure = { action: '次を表示', message: '…', occurredAt }
  └─ busy = false
  ↓(ほぼ同時に)
サーバーが全端末へ SSE state を配信 → useAdminState が新しい state を返す → 画面が変わる
```

### 2-3. phase ごとに押せるボタン

押せない操作はサーバーが `409 INVALID_PHASE` で弾く。ただ当日は「**押したのに怒られた**」より「**そもそも押せない**」ほうが混乱しない。phase を見て先に無効化する。

| ボタン | `waiting` | `question` | `answer` | `finished` | 根拠 |
| --- | --- | --- | --- | --- | --- |
| この問題を出す | ✅ | ✅ | ✅ | ✅ | §3.1 どの phase からでも呼べる |
| 次を表示 | ❌ | ✅ ※ | ❌ | ❌ | §3.2 `question` 以外は 409 |
| 正答を表示 | ❌ | ✅ | ❌ | ❌ | §3.3 `question` 以外は 409 |
| 待機画面を表示 | ❌ | ✅ | ✅ | ✅ | §3.4 どこからでも呼べるが、`waiting` で押す意味は無い |
| クイズを終了 | ✅ | ✅ | ✅ | ❌ | 同上 |

※ 全区切り公開済み(`revealedSegments >= totalSegments`)なら押せない。サーバーは 200 で何もしないが、押しても何も変わらないボタンは混乱のもと。

**上の表とは別に、`busy` の間と確認ポップアップを開いている間は、全部押せない。**

### 2-4. 残り時間は OperationPanel で1回だけ計算する

```
OperationPanel
  remainingTime = useRemainingTime({...})   ← lib のフックを呼ぶのはここ1か所
  remainingSec  = question 中で制限時間ありなら remainingTime、それ以外は null
     ├─→ CurrentStatus のバッジ   remainingSec === 0 なら「回答締切」
     └─→ RemainingTime の表示     remainingSec === 0 なら「締切」
```

**判定を2か所に書かない。** 別々に計算すると、境目の1秒で「バッジは締切なのに残り時間は 00:01」のようにずれる。`ControlPanel` や `RemainingTime` の中で `useRemainingTime` を呼び直さないこと。

**計算には、モニタ・スマホと同じ `lib/useRemainingTime.ts` を使う。** 会場と手元で締切になるタイミングを揃えるため。#107 で `OperationPanel.tsx` の中に書かれた `useDeadlinePassed` は消す(§3-2)。

> ⚠️ **分かっている不具合(別Issueで直す)。** `useRemainingTime` は残り秒数を `useState(0)` で持ち、正しい値が入るのは描画の**後**。そのため**出題した直後の1描画だけ「回答締切」「締切」が一瞬映る。** モニタ・スマホも同じ状態。
>
> #107 の `useDeadlinePassed` はこれを避けるために管理者画面だけ別の計算をしていたが、それだと会場と手元で計算が2種類になる。そこで、#108 では素直に `useRemainingTime` を使い、**フック側を直すIssueを別に立てる**(→ `lib/useRemainingTime` の初回描画の修正)。直れば管理者・モニタ・スマホが一度に直り、#108 のコードは変えなくてよい。
>
> **#108 のレビューでは、この一瞬の締切表示を指摘対象にしない。**

**0秒になっても phase は動かない。** 表示が「締切」に変わるだけで、「正答を表示」は裏方が押すまで起きない(`画面・要件.md` §4)。自動で `showAnswer()` を呼ぶコードは絶対に書かない。

### 3-1. ボタンの文言を `labels.ts` に置く

> 📄 **対象ファイル:** `frontend/src/features/admin/labels.ts`(既存・変更)
> **場所:** ファイルの**一番下**(`export const phaseLabel = …` の行の後ろ)に足す

ボタンに書く文言と、エラー文の「〇〇に失敗しました」の〇〇を**同じ値**にする。違う言葉だと、当日「どのボタンの話?」となる。

⚠️ よくある書き間違い:

- `export const ActionLabel = …` ← **`const` ではなく `type`。** `const` だと `']' expected` のエラーになる
- `const ACTION_LABEL = {` ← **`export` を付ける。** 他のファイルから import するため
- `(typeof ACTION_LABEL)` の後ろで改行しない。1行で書く

> **`(typeof ACTION_LABEL)[keyof typeof ACTION_LABEL]` の読み方**
>
> 1. `typeof ACTION_LABEL` … オブジェクトから型を取り出す → `{ showQuestion: '出題'; advanceText: '次を表示'; … }`
> 2. `keyof typeof ACTION_LABEL` … その型のキーを全部集める → `'showQuestion' | 'advanceText' | …`
> 3. `型[キー]` … そのキーで引いた値を全部集める → `'出題' | '次を表示' | …`
>
> つまり「`ACTION_LABEL` に書いてある文言のどれか」だけを許す型になる。`as const` を付けないと値がただの `string` になり、何でも通ってしまう。

```ts
// ↓ frontend/src/features/admin/labels.ts の一番下に足す

// 進行操作の名前。ボタンの文言と、失敗したときの「〇〇に失敗しました」の両方に使う。
// 2か所で別の言葉にすると、どのボタンが失敗したのか当日照らし合わせられない。
//
// 📝 Issue #108 は動詞句(「この問題を出す」「正答を表示」…)を指定していたが、
//    実装後に実物の画面を見て、PMの判断で下の短い文言(状態名)に変更した。
export const ACTION_LABEL = {
  showQuestion: '出題',
  advanceText: '次を表示',
  showAnswer: '正解',
  resetWaiting: '待機画面',
  resetFinished: '終了',
} as const

export type ActionLabel = (typeof ACTION_LABEL)[keyof typeof ACTION_LABEL]
```

⚠️ **`ConfirmDialog` 自身の文言(`title="正答を表示しますか?"` など、§6-4)は変えない。** あれは `ACTION_LABEL.showAnswer` とは別の、確認ダイアログ専用の文章なので、ボタンの文言(「正解」)と一致していなくてよい。

### 3-4. `OperationPanel` の中で残り時間を求める

> 📄 **対象ファイル:** `frontend/src/features/admin/OperationPanel.tsx`(既存・変更)
> **場所:** `export function OperationPanel` の中の3か所

```tsx
// ↓ frontend/src/features/admin/OperationPanel.tsx の export function OperationPanel の中

// ① 変更前
const deadlinePassed = useDeadlinePassed(state)
// ① 変更後
// 残り秒数。モニタ・スマホと同じフックで計算する(→ 手順書 §2-4)。
// フックは if (state === null) return より前に呼ぶ決まりなので、state が null でも渡せる形にする
const remainingTime = useRemainingTime({
  serverTime: state?.serverTime ?? '',
  timeLimitSec: state?.timeLimitSec ?? null,
  questionStartedAt: state?.questionStartedAt ?? null,
})

if (state === null) return <p>接続中...</p>   // 既存。この行は変えない

// ② 足す(if (state === null) return の行のすぐ下)
// 画面に出す残り時間。null は「残り時間を出さない」。
// useRemainingTime は制限時間なしのときも 0 を返すので、そのまま使うと「締切」扱いになる。
// answer でも timeLimitSec が残っているので phase も見る
const remainingSec =
  state.phase === 'question' && state.timeLimitSec !== null ? remainingTime : null

// ③ 変更前
<CurrentStatus state={state} status={toStatus(state, deadlinePassed)} />
// ③ 変更後
<CurrentStatus state={state} status={toStatus(state, remainingSec)} />
```

`remainingSec` の値の意味:

| 値 | 意味 |
| --- | --- |
| `null` | 残り時間を出さない(`question` 以外 / 制限時間なし) |
| `0` | 締切。phase は `question` のまま動かない(`画面・要件.md` §4) |
| `1` 以上 | 残り秒数 |

⚠️ **`remainingTime` と `remainingSec` を取り違えない。** 以降の部品(`ControlPanel` `RemainingTime`)に渡すのは **`remainingSec`**。`remainingTime` を渡すと、制限時間なしの問題や `waiting` 中に「締切」と出る。

### 3-5. `toStatus` を書き換える

> 📄 **対象ファイル:** `frontend/src/features/admin/OperationPanel.tsx`(既存・変更)
> **場所:** `function toStatus(state: AdminState, deadlinePassed: boolean) { … }` をまるごと置き換える(直前のコメント「会場に出ている状態を決める。…」は残す)

**「締切かどうか」はここで1回だけ決める。**

```ts
// ↓ frontend/src/features/admin/OperationPanel.tsx の function toStatus を置き換える
function toStatus(state: AdminState, remainingSec: number | null): AdminStatus | null {
  if (state.phase === 'answer') return 'answer'
  if (state.phase !== 'question') return null
  // 制限時間なし(null)はいつまでも受付中
  return remainingSec === 0 ? 'closed' : 'accepting'
}
```

**Step 1 が終わった時点の `OperationPanel.tsx` は、上から次の順に並んでいる。**

```
frontend/src/features/admin/OperationPanel.tsx
├── import                          … react の行を消し、useRemainingTime を足した
├── type Props(変更なし)
├── export function OperationPanel  … useRemainingTime を呼び、remainingSec を求める
└── function toStatus               … 引数を remainingSec に変更
    (function useDeadlinePassed は消えている)
```

## 4. Step 2: RemainingTime

### 4-1. 何を出すか

| 条件 | 表示 |
| --- | --- |
| `phase` が `question` 以外 | `--:--`(薄く) |
| `question` で制限時間なし(`remainingSec === null`) | `制限なし` |
| 残りあり | `00:30` |
| 残り0 | `締切`(色を変える) |

```tsx
// ↓ frontend/src/features/admin/parts/RemainingTime.tsx(新規作成)
import type { Phase } from '../../../types'

type Props = {
  phase: Phase
  // OperationPanel が計算した値をそのまま受け取る。ここで計算し直さない(→ 手順書 §2-4)
  remainingSec: number | null
}

// mm:ss。モニタの features/monitor/parts/RemainingTime と同じ書式にする
// (features 間の import は禁止なので書き写す)。会場と手元で表記が違うと読み合わせで困る
function formatTime(seconds: number): string {
  const minutes = Math.floor(seconds / 60)
  const secs = seconds % 60
  return `${String(minutes).padStart(2, '0')}:${String(secs).padStart(2, '0')}`
}

export function RemainingTime({ phase, remainingSec }: Props) {
  return (
    <div className="flex items-baseline gap-4 font-zen-kaku-gothic-new">
      <p className="text-admin-pre-timelimit text-brand">残り時間</p>
      {/* 締切の瞬間に文字数が変わってもボタンが動かないよう、幅を固定する */}
      <p className="min-w-[4.5em] text-admin-timelimit leading-none tabular-nums" aria-live="polite">
        {phase !== 'question' ? (
          <span className="text-neutral-300">--:--</span>
        ) : remainingSec === null ? (
          <span className="text-admin-header">制限なし</span>
        ) : remainingSec === 0 ? (
          <span className="text-red-700">締切</span>
        ) : (
          formatTime(remainingSec)
        )}
      </p>
    </div>
  )
}
```

- 文字サイズは `index.css` にある管理者用トークン(`text-admin-timelimit` 80px / `text-admin-pre-timelimit` 24px)を使う。**モニタ用の `text-p-*` は 85インチ用なので使わない**
- 色は Figma を見て合わせる。上のコードの色は仮
- `tabular-nums` は数字の幅を揃える指定。`00:11` と `00:10` で横幅が変わってチラつくのを防ぐ

⚠️ **`aria-live` は毎秒読み上げられてうるさい場合は外してよい。** 締切の瞬間だけ知らせたいなら、「締切」の `span` にだけ `role="status"` を付ける。

## 5. Step 3: ErrorBanner

### 5-1. 守ること(#20 手順書 §7-3 + Issue のレビュー観点)

1. **どの操作が失敗したかを必ず書く。** `「正答を表示」に失敗しました` + 理由。「赤い字が出た」だけでは当日切り分けられない
2. **勝手に消さない。** 3秒で消えるトーストにしない。消えるのは「閉じる」を押したとき、または**次の操作を始めたとき**だけ

```tsx
      </div>
      <button type="button" onClick={onDismiss} className="shrink-0 rounded-lg border border-red-700 px-3 py-1 text-sm">
        閉じる
      </button>
    </div>
  )
}
```

## 6. Step 4: ConfirmDialog(このIssueで一番重要)

> **この画面の一番怖い事故は、誤操作で正答が会場に漏れること。** 200人が見てしまったら戻せない。

### 6-1. 確認を挟むのは「正答を表示」だけ

全部のボタンに確認が出ると、裏方は**読まずに「はい」を押す癖**がつく。すると本当に止めたい「正答を表示」でも止まらない。**確認は、戻せない操作1つだけに絞るから効く。**

(#110 の貼り付け投入でもこの部品を使い回すので、文言は props で渡せるようにしておく)

### 6-2. 「キャンセルが押しやすい」を具体的にする

焦っている裏方の手の動きを想像して、以下を**全部**満たす。

| # | 要件 | 防ぐ事故 |
| --- | --- | --- |
| 1 | **開いた瞬間、キーボードの焦点は「やめる」にある** | Enter / スペースの連打で表示してしまう |
| 2 | **「やめる」を大きく、目立つ色にする。「表示する」は控えめにする** | 目立つほうを反射で押す |
| 3 | **「やめる」を左(先)に置き、2つのボタンの間を空ける** | 押し損ねて隣を押す |
| 4 | **「表示する」が、元の「正答を表示」ボタンと同じ位置に来ない** | ダブルクリックの2回目がそのまま「表示する」に当たる |
| 5 | **Esc キーで閉じる**(= やめる) | 慌てたときの逃げ道 |
| 6 | **開いている間、背面のボタンは押せない** | ポップアップの外の「正答を表示」をもう一度押す |
| 7 | **ボタンの文言は「はい / いいえ」にしない。** 「やめる」「正答を表示する」と動作を書く | 質問文を読まずに「はい」を押す |
| 8 | **確認を飛ばす隠し操作(Shift+クリック等)を作らない** | — |

4番は Figma のレイアウト次第なので、**`/dev/admin` と実物の両方で、ダブルクリックして確かめる**(§9-3)。

### 6-3. `/dev/admin` で「開いた状態」を見せるための分け方

ポップアップは本来「画面全体に黒い幕を張って、真ん中に箱を出す」。これをプレビューページにそのまま置くと、**プレビューページ全体が幕で覆われて何も見えなくなる。**

そこで2つに分ける。

| 部品 | 中身 | 使う場所 |
| --- | --- | --- |
| `ConfirmDialogCard` | 箱の中身だけ(文言・2つのボタン・焦点・Esc) | `/dev/admin` にそのまま並べる |
| `ConfirmDialog` | 幕 + 真ん中に `ConfirmDialogCard` | 実物の `ControlPanel` |

```tsx
// ↓ frontend/src/features/admin/parts/ConfirmDialog.tsx(新規作成)
import { useEffect, useId, useRef } from 'react'

type Props = {
  title: string
  message: string
  // 実行ボタンの文言。「はい」ではなく動作を書く(例: 正答を表示する)
  confirmLabel: string
  onConfirm: () => void
  onCancel: () => void
}

// 戻せない操作の前に挟む確認の、箱の中身。
//
// 付けるのは「正答を表示」だけ(と #110 の全置換投入)。全部に付けると
// 裏方が読まずに押すようになり、確認の意味が消える(→ #20 手順書 §6)。
//
// 🚫 確認を飛ばす隠し操作を足さないこと。
export function ConfirmDialogCard({ title, message, confirmLabel, onConfirm, onCancel }: Props) {
  const cancelRef = useRef<HTMLButtonElement>(null)
  const titleId = useId()
  const messageId = useId()

  // 開いた直後は「やめる」に焦点を置く。Enter の連打で実行されないようにするため。
  // preventScroll: /dev/admin に複数並べたときにページが勝手にスクロールしないように
  useEffect(() => {
    cancelRef.current?.focus({ preventScroll: true })
  }, [])

  return (
    <div
      role="alertdialog"
      aria-modal="true"
      aria-labelledby={titleId}
      aria-describedby={messageId}
      onKeyDown={(e) => {
        if (e.key === 'Escape') onCancel()
      }}
      className="w-full max-w-[480px] rounded-3xl bg-surface p-8 font-zen-kaku-gothic-new text-black shadow-xl"
    >
      <h2 id={titleId} className="text-admin-header text-brand">
        {title}
      </h2>
      <p id={messageId} className="mt-4 text-admin-func-label">
        {message}
      </p>
      {/* 「やめる」を先・大きく。焦って押すときに手前へ手が伸びるため */}
      <div className="mt-8 flex flex-wrap items-center gap-6">
        <button
          type="button"
          ref={cancelRef}
          onClick={onCancel}
          className="min-w-40 flex-1 rounded-xl bg-brand px-6 py-4 text-admin-func-label-l text-white focus-visible:outline-4 focus-visible:outline-offset-2 focus-visible:outline-brand"
        >
          やめる
        </button>
        <button
          type="button"
          onClick={onConfirm}
          className="rounded-xl border-2 border-red-700 px-4 py-2 text-admin-func-label text-red-700"
        >
          {confirmLabel}
        </button>
      </div>
    </div>
  )
}

// 画面の上に幕を張って、真ん中に確認の箱を出す。
// 幕が背面のクリックを受け止めるので、ポップアップの外のボタンは押せない。
// 幕のクリックでは閉じない(慌てて外を押したときに、何も起きないほうが安全)。
export function ConfirmDialog(props: Props) {
  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/50 p-4">
      <ConfirmDialogCard {...props} />
    </div>
  )
}
```

**色・大きさは Figma に合わせて変えてよい。ただし §6-2 の表を崩さないこと。** 「Figma では『はい』が右で目立つ色だった」なら、Figma 側を直す提案を PM に上げる。

> **`window.confirm()` ではだめなのか。** 要件の大半は満たせる。ただし焦点がどちらにあるか・ボタンの文言・配置をブラウザ任せにするしかなく、§6-2 の 2・3・7 を保証できない。また `/dev/admin` に並べられない。

> **`<dialog>` 要素の `showModal()` を使わないのか。** 背面を押せなくする・Esc で閉じるを自動でやってくれる良い仕組み。ただし `showModal()` は1ページに1つしか「最前面」を持てないので、`/dev/admin` に開いた状態を並べられない。今回はプレビュー要件を優先して `div` で作る。

## 7. Step 5: ControlPanel

### 7-1. 部品を作る

> 📄 **対象ファイル:** `frontend/src/features/admin/parts/ControlPanel.tsx`(**新規作成**)
> **場所:** ファイルを新しく作り、下のコードを全部書く。ボタン1個分の `ControlButton` も**同じファイルの一番下**に書く

```tsx
// ↓ frontend/src/features/admin/parts/ControlPanel.tsx(新規作成)
import { useState } from 'react'
import type { AdminState } from '../../../types'
import { ACTION_LABEL } from '../labels'
import { ConfirmDialog } from './ConfirmDialog'
import { RemainingTime } from './RemainingTime'

type Props = {
  state: AdminState
  // OperationPanel が計算した残り秒数(→ 手順書 §2-4)
  remainingSec: number | null
  // 送信中。true の間は操作盤全体を押せなくする
  busy: boolean
  onAdvanceText: () => void
  onShowAnswer: () => void
  onReset: (to: 'waiting' | 'finished') => void
}

// 進行の操作ボタン。
//
// 押せない操作はサーバーが 409 INVALID_PHASE で弾くが、当日は
// 「押したのに怒られた」より「押せない」ほうが混乱しないので、先に無効にする(→ 手順書 §2-3)。
export function ControlPanel({ state, remainingSec, busy, onAdvanceText, onShowAnswer, onReset }: Props) {
  const [confirmingAnswer, setConfirmingAnswer] = useState(false)

  const isQuestion = state.phase === 'question'
  // 開いている間に別の端末から phase が変わったら、確認ごと閉じる
  // (出す必要の無くなった確認に「表示する」を押させない)
  const dialogOpen = confirmingAnswer && isQuestion
  // 送信中と、確認を開いている間は、全ボタンを押せなくする。
  // 押したボタン1つだけを止めると、「次を表示」の応答待ちに「正答を表示」を押せてしまう
  const locked = busy || dialogOpen

  const canAdvance = isQuestion && state.revealedSegments < state.totalSegments

  return (
    <section className="w-full max-w-[440px] rounded-3xl border border-border-soft bg-surface px-6 py-4 font-zen-kaku-gothic-new">
      <header className="flex items-center justify-between">
        <h2 className="text-admin-header text-brand">操作パネル</h2>
        {busy && <p className="text-admin-func-label text-brand">送信中…</p>}
      </header>

      <RemainingTime phase={state.phase} remainingSec={remainingSec} />

      {/* 進行の2つ。当日いちばん押すので上に置く */}
      <div className="mt-4 grid grid-cols-2 gap-3">
        <ControlButton label={ACTION_LABEL.advanceText} disabled={locked || !canAdvance} onClick={onAdvanceText} />
        <ControlButton
          label={ACTION_LABEL.showAnswer}
          disabled={locked || !isQuestion}
          onClick={() => setConfirmingAnswer(true)}
        />
      </div>

      {/* 画面を切り替える2つ。進行ボタンと離して置き、見た目でも別グループにする。
          待機と終了は「会場に何が映るか」が違うので、行き先を文言で書く */}
      <div className="mt-6 border-t border-border-soft pt-4">
        <p className="text-sm">会場の画面を切り替える(出題済みの記録は消えます)</p>
        <div className="mt-2 grid grid-cols-2 gap-3">
          <ControlButton
            label={ACTION_LABEL.resetWaiting}
            sub="まもなく始まります + 参加QR"
            disabled={locked || state.phase === 'waiting'}
            onClick={() => onReset('waiting')}
          />
          <ControlButton
            label={ACTION_LABEL.resetFinished}
            sub="終了メッセージ + アンケートQR"
            disabled={locked || state.phase === 'finished'}
            onClick={() => onReset('finished')}
          />
        </div>
      </div>

      {dialogOpen && (
        <ConfirmDialog
          title="正答を表示しますか?"
          message="モニタと参加者のスマホに、正答が表示されます。表示すると取り消せません。"
          confirmLabel="正答を表示する"
          onConfirm={() => {
            setConfirmingAnswer(false)
            onShowAnswer()
          }}
          onCancel={() => setConfirmingAnswer(false)}
        />
      )}
    </section>
  )
}

function ControlButton({
  label,
  sub,
  disabled,
  onClick,
}: {
  label: string
  sub?: string
  disabled: boolean
  onClick: () => void
}) {
  return (
    <button
      type="button"
      onClick={onClick}
      disabled={disabled}
      className="rounded-xl bg-brand px-4 py-3 text-admin-func-label text-white disabled:cursor-not-allowed disabled:opacity-40"
    >
      {label}
      {sub !== undefined && <span className="block text-xs font-normal">{sub}</span>}
    </button>
  )
}
```

### 7-2. 見た目で守ること

- **「待機画面を表示」と「クイズを終了」が区別できること。** 文言だけでなく、並び・色・補足の1行(何が映るか)で分かるようにする。Issue のレビュー観点

## 8. Step 6: ShowQuestionForm

### 8-1. 秒数の入力欄のルール

| 入力 | 扱い |
| --- | --- |
| 初期値 | **`30`** |
| `5`〜`120` の整数 | OK。その値を送る |
| 空欄 | NG「秒数を入れてください」 |
| `4` 以下 / `121` 以上 | NG「5〜120秒の範囲で入れてください」 |
| `30.5` など小数 | NG「整数で入れてください」(サーバーは `int` で受けるので 400 になる) |

**NG のときは、ボタンを押せなくし、理由を入力欄のすぐ下に出す。** 押してから `INVALID_REQUEST` で怒られる作りにしない。

> **なぜ空欄を許さないのか(#20 手順書からの変更)。** #20 の手順書では「空なら省略して送り、サーバーが30秒を当てる」だった。Issue #108 で「既定30」に変えた。空欄を許すと、裏方が消した後に**何秒で出題されるのか画面から読めない**。最初から `30` と書いてあれば、見たとおりの秒数で出る。

### 8-2. 「選んで出す」方式を崩さない

- **「次の問題へ」ボタンを作らない。** 2回押すと問題が飛ぶ。「この問題を出す」なら、2回押しても同じ問題が出るだけ
- 選んだ問題が**何か**を、ボタンのすぐ近くに書く(ID / 形式 / 難易度 / 問題文の頭)。押す前に目で確かめられるように
- 選んだ問題が**いま出題中の問題と同じ**なら、「出題中の問題を最初からやり直します(タイマーも戻ります)」と注意を出す。押せるようにはしておく(§3.1 でやり直しは正式な操作)
- 選んだ問題が**出題済み**(`asked`)なら、「出題済みの問題です」と出す。これも押せるようにはしておく

```tsx
// ↓ frontend/src/features/admin/parts/ShowQuestionForm.tsx(新規作成)
import { useId } from 'react'
import type { QuestionListItem } from '../../../types'
import { ACTION_LABEL, difficultyLabel, questionTypeLabel } from '../labels'

// サーバーの検証(backend/internal/event/progress.go)と同じ範囲。変えるときは両方直す
const MIN_SEC = 5
const MAX_SEC = 120

type Props = {
  // 問題一覧(#109)で選んでいる問題。未選択なら null
  selected: QuestionListItem | null
  // question phase で出している問題の id。それ以外は null
  currentQuestionId: number | null
  // 入力欄の文字列。状態は OperationPanel が持つ(/dev/admin で範囲外の見た目を並べるため)
  timeLimitInput: string
  busy: boolean
  onTimeLimitInputChange: (value: string) => void
  onSubmit: (questionId: number, timeLimitSec: number) => void
}

// 入力欄の文字列を検査する。問題なければ null、あれば裏方に見せる理由を返す
export function checkTimeLimit(input: string): string | null {
  if (input.trim() === '') return `秒数を入れてください(${MIN_SEC}〜${MAX_SEC})`
  const sec = Number(input)
  if (!Number.isInteger(sec)) return '秒数は整数で入れてください'
  if (sec < MIN_SEC || sec > MAX_SEC) return `${MIN_SEC}〜${MAX_SEC}秒の範囲で入れてください`
  return null
}

// 選んだ問題を出題する。
// 「次の問題へ」ではなく「この問題を出す」方式なので、二度押ししても同じ問題が出るだけで事故らない
export function ShowQuestionForm({
  selected,
  currentQuestionId,
  timeLimitInput,
  busy,
  onTimeLimitInputChange,
  onSubmit,
}: Props) {
  const inputId = useId()
  const errorId = useId()
  const inputError = checkTimeLimit(timeLimitInput)
  const canSubmit = !busy && selected !== null && inputError === null

  return (
    <section className="w-full max-w-[440px] rounded-3xl border border-border-soft bg-surface px-6 py-4 font-zen-kaku-gothic-new">
      <h2 className="text-admin-header text-brand">選択中の問題</h2>

      {selected === null ? (
        <p className="mt-2 text-admin-func-label text-neutral-500">問題一覧から1問選んでください</p>
      ) : (
        <div className="mt-2 text-admin-func-label">
          <p>
            ID {selected.id} / {questionTypeLabel(selected.type)} / {difficultyLabel(selected.difficulty)}
          </p>
          <p className="[overflow-wrap:anywhere]">{selected.textPreview}</p>
          {selected.id === currentQuestionId ? (
            <p className="text-sm text-red-700">出題中の問題を最初からやり直します(タイマーも戻ります)</p>
          ) : (
            selected.asked && <p className="text-sm text-red-700">出題済みの問題です</p>
          )}
        </div>
      )}

      <form
        className="mt-4 flex flex-wrap items-start gap-4"
        onSubmit={(e) => {
          e.preventDefault()
          // selected === null も書く。canSubmit だけだと TypeScript が null を消せず、selected.id が型エラーになる
          if (!canSubmit || selected === null) return
          onSubmit(selected.id, Number(timeLimitInput))
        }}
      >
        <div>
          <label htmlFor={inputId} className="block text-sm">
            制限時間(秒)
          </label>
          <input
            id={inputId}
            type="number"
            inputMode="numeric"
            min={MIN_SEC}
            max={MAX_SEC}
            step={1}
            value={timeLimitInput}
            disabled={busy}
            aria-invalid={inputError !== null}
            aria-describedby={inputError === null ? undefined : errorId}
            onChange={(e) => onTimeLimitInputChange(e.target.value)}
            className={`w-24 rounded-lg border px-3 py-2 ${inputError === null ? 'border-border-soft' : 'border-red-700'}`}
          />
          {/* 出ていないときも高さを取っておき、ボタンが上下に動かないようにする */}
          <p id={errorId} className="min-h-5 text-sm text-red-700">
            {inputError}
          </p>
        </div>
        <button
          type="submit"
          disabled={!canSubmit}
          className="mt-5 rounded-xl bg-brand px-6 py-3 text-admin-func-label text-white disabled:cursor-not-allowed disabled:opacity-40"
        >
          {ACTION_LABEL.showQuestion}
        </button>
      </form>
    </section>
  )
}
```

⚠️ **`type="number"` の癖。** 数字でない文字を打つと、ブラウザは `value` を空文字として渡してくる。だから「空欄」の判定で拾える。

⚠️ **Enter キーで送信される。** 入力欄で Enter を押すと `<form>` の送信になる。出題は「選んで出す」方式で2回押しても事故らないので、これは許容する。**「正答を表示」を `<form>` の中に入れないこと**(Enter で確認を飛ばす経路になりうる)。

5. Enter → ポップアップが閉じる。モニタは変わらない
6. 「正答を表示」→「正答を表示する」→ モニタに正答。残り時間が `--:--` に
7. 「待機画面を表示」→ モニタが待機画面。「出題中の問題」パネルが「待機中」
8. `curl` で出題し直す →「クイズを終了」→ モニタが終了画面(アンケートQR)
9. DevTools の Network を「Offline」にして「待機画面を表示」→ `「待機画面を表示」に失敗しました` が出て、閉じるまで消えない
10. DevTools の Application → Local Storage で `adminToken` を書き換えてから何か押す → ログイン画面に戻る

### ⚠️ 「待機画面を表示」を途中で押すと、出題済みの記録が全部消える

- → 問題一覧(#109)の「出題済み」の印も全部消え、どれを出したか分からなくなる

#20 の手順書 §6 は「リセットは出し直せばよい」ので確認不要としていたが、**この記録は出し直しでは戻らない。**

選択肢:

| 案 | 内容 | 懸念 |
| --- | --- | --- |

| C | API を変えて、`waiting` では `asked` を消さない | バックエンドと API仕様書の変更が要る。このIssueの範囲外 |

**本書は A で書いてある。** B か C にするなら、§7 のコードと §10 のプレビューを直す。
