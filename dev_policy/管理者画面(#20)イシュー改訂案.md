## 0. 前提となった決定(2026-09-12)

### 決定1. 状態バッジは phase ではなく「会場に出ている状態」

モニタとスマホは**すでに3状態のバッジを実装済み**で、文言も色トークンも決まっている。

| status | 文言 | 色トークン | 実装場所 |
| --- | --- | --- | --- |
| `accepting` | 回答受付中 | `bg-accepting-answer` | `monitor/parts/StatusPanel.tsx` / `phone/parts/QuestionLayout.tsx` |
| `closed` | 回答締切 | `bg-closed-answer` | 同上 |
| `answer` | 正解発表 | `bg-live` | 同上 |

**管理者画面のバッジもこの3つに揃える。** 裏方の手元と会場の表示が同じ言葉になっていないと、
「いま画面に何が出ているか」を口頭で確認できない。

これは `phase` とは別の概念であることに注意する。`closed`(回答締切)は phase ではなく、
残り0秒でクライアントが自分で切り替える**表示状態**(API仕様書 第6版 ⑤)。

導出はこうなる。

```
phase === 'answer'                    → answer(正解発表)
phase === 'question' && 残り > 0      → accepting(回答受付中)
phase === 'question' && 残り === 0    → closed(回答締切)
phase === 'waiting' / 'finished'      → バッジを出さない
```

`waiting` / `finished` はバッジ無しにし、パネル本体に `labels.ts` の `phaseLabel`(待機中 / 終了)を出す。
モニタもこの2つではバッジを出していないので、挙動が揃う。

> **`labels.ts` の `PHASE_LABEL` はそのまま残す。** バッジとは用途が違う(バッジ=会場の状態、`phaseLabel`=空状態の文言)。

### 決定2. 問題形式の表記は Figma に合わせる

`labels.ts` の `arunashi: 'あるなし'` を **`'有無'`** に変える。Figma の問題リストのバッジがそうなっているため。

### 決定3. 「選択中の問題」は新規イシューにする

#109 には混ぜない。`GET /api/admin/questions/:id`(§4.2)への依存が増えるため。

### 決定4. #79(§4.2 のサーバー実装)は PM が自分で実装する

→ [`問題詳細API(#79)実装手順書.md`](./問題詳細API\(#79\)実装手順書.md)

### ⚠️ PR #99 からの変更が必要

### 表示するもの

Figma の「出題中の問題」パネルに並んでいる項目。すべて `AdminState.question` から取れる。

- **`askedCount`(第何問か)。** Figma にある ID は問題そのものの番号で、これとは別物。当日司会と読み合わせるのは `askedCount` のほう。ただし **`waiting` / `finished` では必ず `0` になる**ので出さない(→ API仕様書 第10版 ③)
- **`revealedSegments` / `totalSegments`(何セグメントまで公開しているか)。** 未公開の区切りには印を付ける。裏方が先に読み上げると事故る

### 状態バッジ

| status | 文言 | 色トークン |
| --- | --- | --- |

| `closed` | 回答締切 | `bg-closed-answer` |
| `answer` | 正解発表 | `bg-live` |

- `waiting` / `finished` ではバッジを出さず、パネル本体に `phaseLabel`(待機中 / 終了)を出す

## 2. #108【管理者画面3/6】進行操作と「正答を表示」の確認ポップアップ

> ### 差し替え範囲
> 「## やること」と「## ⚠️ 落とし穴」と「## レビュー観点」「## 受け入れ条件」。冒頭の2行はそのまま。

### やること

| ファイル | 内容 |
| --- | --- |
| `features/admin/parts/ControlPanel.tsx` | 次を表示 / 正答を表示 / 待機画面を表示 / クイズを終了 |
| `features/admin/parts/RemainingTime.tsx` | 残り時間(Figma の「操作パネル」の 00:30) |
| `features/admin/parts/ShowQuestionForm.tsx` | 秒数入力 + 出題ボタン |
| `features/admin/parts/ConfirmDialog.tsx` | 確認ポップアップ |
| `features/admin/parts/ErrorBanner.tsx` | 操作が失敗したときの表示 |

**確認ポップアップをこのIssueに含める。** 手順書は Step 6 として分けているが、**操作盤は4つの操作で1つの機能**であり、分けると「操作盤として成立しているか」がレビューで見えなくなるため。ただし受け入れ条件では独立に確認する。

### ⚠️ Figma に描かれていないが必ず作るもの

Figma の「操作パネル」にあるボタンは「正解を表示」「待機画面を表示」の2つだけ。**足りない。**

| 足すもの | 無いとどうなるか |
| --- | --- |
| 「次を表示」(`advanceText`) | 問題文が区切りごとに公開されない(`revealedSegments` が進まない) |
| 「クイズを終了」(`reset('finished')`) | 終了画面(アンケートQR)に到達できない |
| 秒数の入力欄(既定30・5〜120) | 制限時間を指定できない |
| 確認ポップアップ | 正答の誤爆を止められない(**手順書 §6 の最重要要件**) |
| エラー表示 | 操作が失敗したことに気づけない |

Figma の「待機画面を表示」は `reset('waiting')` に当たる。**終了と待機の2種類があることが画面上で区別できること。**

### ⚠️ 残り時間はこのイシューで出す

Figma の「操作パネル」にある「残り時間 00:30」を実装する。`lib/useRemainingTime.ts` が既にある。

- 計算に使う `serverTime` / `timeLimitSec` / `questionStartedAt` は `OperationPanel`(#107)から `props` で降ってくる
- **0秒になっても勝手に正答へは進まない。** 表示が「締切」に変わるだけ(→ `画面・要件.md` §4)

### ⚠️ 落とし穴(手順書 §6 / §10)

#### 「正答を表示」には確認ポップアップを必ず挟む

> **この画面の一番怖い事故は、誤操作で正答が会場に漏れること。**

- **キャンセルが押しやすい位置にあること。** 焦って連打したときに「はい」に当たらないように
- ポップアップを飛ばせる隠し操作を作らない

#### 「次へ」ではなく「この問題を出す」方式にする

問題を**選んで**出題する。「次へ」方式にすると、ボタンを2回押したときに問題が飛ぶ。選択方式なら2回押しても同じ問題が出るだけで事故にならない(**連打耐性のための設計**)。

#### 秒数の入力欄

既定30、範囲 **5〜120**。範囲外はサーバーが `INVALID_REQUEST` を返すが、**押す前に画面で止める**こと。
Figma では「選択中の問題」パネルの出題ボタンの近くに置く。

#### 操作中はボタンを無効化する

押している間は**操作盤全体**を無効化する。押したボタン1つだけを無効化すると、「次を表示」の応答待ち中に「正答を表示」を押せてしまう。

### レビュー観点

- [ ] ボタンが4つある(次を表示 / 正答を表示 / 待機画面を表示 / クイズを終了)
- [ ] 「正答を表示」で確認ポップアップが出る／キャンセルが押しやすい位置にある
- [ ] 出題が「選んで出す」方式になっている(「次へ」になっていない)
- [ ] 秒数が 5 未満・120 超で、送信前に画面で止まる
- [ ] 待機に戻すのと終了するのが、画面上で区別できる
- [ ] 残り0秒で表示が「締切」に変わり、phase は動かない
- [ ] 操作中は操作盤全体が無効になる
- [ ] 失敗したとき、**どの操作に失敗したか**が分かる文言が出る

### 受け入れ条件

- [ ] 上記レビュー観点をすべて満たす
- [ ] `/dev/admin` に `ControlPanel` / `ShowQuestionForm` / `ConfirmDialog` / `RemainingTime` / エラー表示 が並んでいる
  - [ ] ConfirmDialog は**開いた状態**でも確認できる
  - [ ] busy(送信中)の見た目も確認できる
  - [ ] 残り時間は 残あり / 0秒(締切) の2状態
- [ ] 各パネルが `props` だけで描画でき、通信に依存していない

## 5. 【新規】管理者画面 選択中の問題パネル
