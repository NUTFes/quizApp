## 0. 何を作るのか

**「いま会場のモニタに何が映っているか」を、裏方の手元に文字で出すパネルを1枚作る。**

Figma の「出題中の問題」パネル(`figma-design/出題中の問題パネル.png`)がそれ。見た目はこう。

```
┌─────────────────────────────────────────────┐
│  出題中の問題            ( 回答受付中 )      │ ← 見出し + バッジ
│                                             │
│  ID        5                                │
│  問題形式   2択                              │
│  難易度     難しい                           │
│  制限時間   30秒                             │
│  問題文     この問題文は / スラッシュ区切りで  │
│            / 少しずつ表示される (未公開)      │
│  選択肢     A: ブラジル                      │
│            B: カナダ                        │
│  正答      B: カナダ                         │
└─────────────────────────────────────────────┘
```

**当日これを見て何をするのか。** 裏方は会場の85インチを見ながら操作するとは限らない。
「次に読み上げるのはどこまでか」「正答はどれか」「もう締め切ったか」を**手元だけで判断できる**必要がある。
だからこのパネルは、正答を含めて全部出す(管理者だけがサーバーから正答を受け取れる)。

### このイシューで作らないもの

Figma の管理者画面には他にもパネルが並んでいるが、**触らない。**

| パネル | 担当 |
| --- | --- |
| 画面プレビュー(モニタ・スマホの縮小表示) | #111 |
| 問題リスト | #109 |
| 操作パネル(ボタン群・残り時間の数字) | #108 |
| 選択中の問題 | #116 |
| パネル全体の配置 | #118 |

**後続イシューのパーツの空ファイルも作らない。** #106 が空の `OperationPanel.tsx` を置いたのは、
認証の分岐に行き先が無いとビルドが通らなかったからで、先回りして枠を用意する方針ではない。

## 2. 全体の形(これを先に頭に入れる)

**データは1本の流れで降りてくる。パネルは受け取って描くだけ。**

```
サーバー
  │  SSE で state が飛んでくる(状態が変わったときだけ)
  ▼
useAdminState()            … lib/useEventState.ts。実装済み。触らない
  │  AdminState | null
  ▼
OperationPanel             ← あなたが書く「器」。通信と計算はここだけ
  │  ├ 残り時間を計算(useRemainingTime)
  │  └ バッジの status を決める
  │
  └──▶ CurrentStatus { state, status }
          └──▶ StatusBadge { status }
```

**なぜ器とパネルを分けるのか。** パネルが自分で通信すると、`/dev/admin`(デザイン確認ページ)で描画できなくなる。
トークンも `fetch` も無い場所で、`props` を渡すだけで全パターンを並べられる形にしておく。

### 3-1. `labels.ts` — 1行直す

サーバーは `hard` や `two_choice` のような英語をそのまま返す。日本語にするのはフロントの仕事。
このファイルはもう作ってある(`fbc6492`)。直すのは1行だけ。

```ts
arunashi: '有無',   // 'あるなし' から変更。Figma のバッジに合わせる
```

`PHASE_LABEL`(待機中 / 出題中 / 正答発表 / 終了)は**消さない。** §3-2 のバッジとは使う場所が違う。

### 3-2. `StatusBadge.tsx` — 色付きのバッジ1個

**何をするパーツか。** 渡された状態に応じて、文言と背景色が変わるバッジを1個描く。それだけ。

**なぜ必要か。** 裏方が「いま受付中か、もう締め切ったか」を一瞬で判断するため。
**モニタとスマホが同じバッジを既に出している**ので、文言も色も同じにする。
会場と手元で言葉が違うと、口頭で状態を確認できない。

```tsx
// features/admin/parts/StatusBadge.tsx

// 会場に出ている状態。phase とは別物であることに注意(§3-4)
export type AdminStatus = 'accepting' | 'closed' | 'answer'

const STATUS = {
  accepting: { label: '回答受付中', color: 'bg-accepting-answer' },
  closed:    { label: '回答締切',   color: 'bg-closed-answer' },
  answer:    { label: '正解発表',   color: 'bg-live' },
} as const satisfies Record<AdminStatus, { label: string; color: string }>

export function StatusBadge({ status }: { status: AdminStatus }) {
  return (
    <span className={`rounded-full px-6 py-2 ${STATUS[status].color}`}>
      {STATUS[status].label}
    </span>
  )
}
```

- 文言と色トークンの出どころは `features/monitor/parts/StatusPanel.tsx`。**表は書き写す。import はしない**(手順書 §3 で features 間の参照を禁止している)
- `waiting` / `finished` のときは**このコンポーネントを描画しない**。親が出し分ける。モニタもその2つではバッジを出していない

### 3-3. `CurrentStatus.tsx` — パネル本体

**何をするパーツか。** `props` で受け取った状態を、Figma の表の形に並べて描く。**それ以外は何もしない。**
通信しない、`localStorage` を見ない、時間も数えない。**渡されたものを描くだけ。**

**受け取るもの。**

```tsx
type Props = {
  state: AdminState              // サーバーから来た状態まるごと
  status: AdminStatus | null     // 親が決めたバッジの状態。null ならバッジを出さない
}
```

**残り時間そのものは受け取らない。** 「締め切ったかどうか」の判断は親がして、結果だけを `status` で渡す。
パネルは数えない・判断しない・描くだけ、を守る。

**描くもの。** 上から順に。

| 行 | 出す値 | 注意 |
| --- | --- | --- |
| 見出し + バッジ | 「出題中の問題」+ `StatusBadge` | `waiting` / `finished` ではバッジを出さない |
| 第何問 | `state.askedCount` | **`waiting` / `finished` では出さない**(必ず0になるため) |
| ID | `question.id` | 桁揃えはしない |
| 問題形式 | `questionTypeLabel(question.type)` | 「2択」。日本語にする |
| 難易度 | `difficultyLabel(question.difficulty)` | 「難しい」 |
| 制限時間 | `state.timeLimitSec` | `null` なら「なし」 |
| 問題文 | `question.textSegments` を区切りごとに | **未公開の区切りに印を付ける** |
| 公開状況 | `revealedSegments` / `totalSegments` | 「2 / 3 区切り」 |
| 選択肢 | `question.choices` | `A: ブラジル` の形 |
| 正答 | `correctChoiceId` + その選択肢のテキスト | `B: カナダ` の形 |

**骨組み。**

```tsx
export function CurrentStatus({ state, status }: Props) {
  const question = state.question

  // waiting / finished は「出している問題が無い」状態。表を出さずに終わる
  if (question === null) {
    return (
      <section>
        <h2>出題中の問題</h2>
        <p>{phaseLabel(state.phase)}</p>   {/* 待機中 / 終了 */}
      </section>
    )
  }

  const correct = question.choices.find((c) => c.id === question.correctChoiceId)

  return (
    <section>
      <header>
        <h2>出題中の問題</h2>
        {status !== null && <StatusBadge status={status} />}
      </header>

      <Row label="第何問">第{state.askedCount}問</Row>
      <Row label="ID">{question.id}</Row>
      <Row label="問題形式">{questionTypeLabel(question.type)}</Row>
      <Row label="難易度">{difficultyLabel(question.difficulty)}</Row>
      <Row label="制限時間">
        {state.timeLimitSec === null ? 'なし' : `${state.timeLimitSec}秒`}
      </Row>

      <Row label="問題文">
        {question.textSegments.map((segment, i) => (
          <span key={i}>
            {segment}
            {/* まだモニタに出ていない区切り。裏方が先に読み上げると事故る */}
            {i >= state.revealedSegments && '（未公開）'}
          </span>
        ))}
      </Row>
      <Row label="公開状況">
        {state.revealedSegments} / {state.totalSegments} 区切り
      </Row>

      <Row label="選択肢">
        {question.choices.map((c) => (
          <p key={c.id}>{c.id}: {c.text}</p>
        ))}
      </Row>
      <Row label="正答">
        {correct === undefined ? '未設定' : `${correct.id}: ${correct.text}`}
      </Row>
    </section>
  )
}

// ラベルと値が並ぶ行。Figma の表がこの形の繰り返しになっている
function Row({ label, children }: { label: string; children: ReactNode }) {
  return (
    <div className="flex gap-8">
      <span className="w-24 font-bold">{label}</span>
      <div>{children}</div>
    </div>
  )
}
```

> 📌 `Row` は**このファイルの中に置く。** #116 の「選択中の問題」パネルが似た表を作るが、
> **共通部品にするのは両方できてから**(#118)。先に共通化しない。

### 3-4. `OperationPanel.tsx` — 通信と計算をする器

**何をするパーツか。** サーバーに繋いで状態を受け取り、残り時間を計算し、
バッジに渡す `status` を決めて、パネルに配る。**画面に出すものは持たない**(パネルを並べるだけ)。

いまは #106 が置いた空のコンポーネントになっている。これを中身のあるものに差し替える。

```tsx
export function OperationPanel() {
  // SSE で繋ぎっぱなしにして、状態が変わるたびに新しい state を受け取る。
  // 再接続時に GET /api/state を1回取り直す処理はフックの中に実装済み。自分で書かない
  const state = useAdminState()          // AdminState | null

  // ⚠️ フックは早期 return より前に呼ぶ。下の if の後ろに書くと React の規則違反で落ちる
  const remainingTime = useRemainingTime({
    serverTime: state?.serverTime ?? '',
    timeLimitSec: state?.timeLimitSec ?? null,
    questionStartedAt: state?.questionStartedAt ?? null,
  })

  if (state === null) return <p>接続中...</p>

  return (
    <div>
      <CurrentStatus state={state} status={toStatus(state, remainingTime)} />
      {/* 以降のパネルは #108 以降でここに足していく。縦に並べるだけでよい(配置は #118) */}
    </div>
  )
}
```

**バッジの status を決める関数も、このファイルに書く。** これは `phase` の言い換えではないので、
`labels.ts` には置かない。決める場所を1箇所にして、#108 にも同じ値を配れるようにする。

```tsx
// 会場に出ている状態を決める。バッジを出さないときは null を返す
function toStatus(state: AdminState, remainingTime: number): AdminStatus | null {
  if (state.phase === 'answer') return 'answer'
  if (state.phase !== 'question') return null        // waiting / finished はバッジなし

  // ⚠️ 「残り0秒なら締切」だけで書かないこと(→ §4)。
  //    制限時間なしの出題(timeLimitSec === null)でも remainingTime は 0 になるため、
  //    出した瞬間から「回答締切」と表示されてしまう
  const hasTimeLimit = state.timeLimitSec !== null && state.questionStartedAt !== null
  if (hasTimeLimit && remainingTime === 0) return 'closed'
  return 'accepting'
}
```

> **PR #99 の `OperationPanel` は持ってこない。** あれは `getAdminState()` を操作のたびに叩く作りで、
> SSE を使っていない。同じ仕組みを二重に持つことになる。

## 4. 落とし穴

### ⚠️ 「残り0秒 = 締切」と書くとバグる

`useRemainingTime` は、**制限時間が設定されていないとき(`timeLimitSec === null`)も 0 を返す。**

出題APIの秒数指定は任意なので、時間無制限の出題は実際に起こる。
素直に「残り0なら closed」と書くと、**出した瞬間から「回答締切」と表示される。**

```
closed にしてよいのは、timeLimitSec があり、かつ残りが 0 のときだけ
```

> 📌 モニタ画面(`features/monitor/views/QuestionView.tsx`)も同じ書き方をしている。
> **#107 では直さない。** 別イシューとして PM に報告する(管理者画面のPRでモニタ画面を触ると範囲が壊れる)。

### ⚠️ `features/monitor/` `features/phone/` から import しない

手順書 §3 の決まり。バッジの表は書き写す。**ただし文言と色トークンは1文字も変えない。**

### ⚠️ 残り時間の数字(00:30)は出さない

Figma の「操作パネル」にあるカウントダウンは #108 の担当。#107 が出すのはバッジだけ。
計算は `OperationPanel` で1回だけ行い、#108 にも同じ値を配る(判定を2箇所に書かない)。

### 🔒 やってはいけないこと

- **`dangerouslySetInnerHTML` を使わない。** この画面は `localStorage` にトークンを持つ
- **サーバーの `error.message` をそのまま画面に出さない。** 表示する日本語はフロントが持つ
- **トークンを `console.log` に出さない。** 必要なら `token.length`
- **モックに本番の問題データ・正答を入れない。** このリポジトリは公開されている
