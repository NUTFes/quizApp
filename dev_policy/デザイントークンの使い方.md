# デザイントークンの使い方

3画面（#18 スマホ / #19 モニタ / #20 管理）の実装担当者向け。**Tailwind を触ったことがある前提で、このプロジェクト固有の部分だけ**を書いてある。

関連: Issue #52 / [`frontend/src/index.css`](../frontend/src/index.css)

---

## 0. なぜトークンを使うのか

**色と書体が、まだ確定していないから。**

`docs/実装要件/画面・要件.md` §9 のとおり、プライマリカラー（パンフ・HPの青）とフォントは運営の判断待ちです。**本番直前に変わる可能性があります。**

ここで各自が `text-[#192085]` と直接書いていると、確定した瞬間に**3画面ぜんぶを grep して置換する作業**が発生します。人数も時間もない中で、それは事故のもとです。

```
❌  className="text-[#192085]"     → 色が変わったら全部直す
✅  className="text-brand"         → index.css の1行を直せば全部変わる
```

トークンは「後で変わるものに、変わらない名前をつけておく」ための仕組みです。それ以上の意味はありません。

---

## 1. 3種類あります

`frontend/src/index.css` の `@theme` に定義されています。**このファイルは Figma から自動生成した値を貼ったもので、手で編集しません**（→ §6）。

| 種類 | 定義の書き方 | 使うときのクラス |
| --- | --- | --- |
| 色 | `--color-brand: #192085;` | `bg-brand` `text-brand` `border-brand` |
| 書体 | `--font-zen-kaku-gothic-new: ...;` | `font-zen-kaku-gothic-new` |
| 文字 | `--text-quiz-header: 17px;` | `text-quiz-header` |

Tailwind が**変数名からクラス名を自動で作ります。** `--color-` を取った残りがクラス名になる、と覚えてください。

### 色（15個）

```
brand             accent          canvas          surface
border-soft       info            live
maru              batsu
choice-a          choice-b        choice-c        choice-d
accepting-answer  closed-answer
```

`bg-` `text-` `border-` のどれにも使えます。透明度もつけられます。

```tsx
<div className="bg-canvas">
  <p className="text-brand">問題文</p>
  <div className="border border-border-soft" />
  <div className="bg-brand/20" />   {/* 20% の透明度 */}
</div>
```

### 文字（約65個）

**ここが Tailwind の一般的な使い方と違う部分**なので、よく読んでください。

`--text-*` は**サイズだけではありません。** 行間・字間・太さがセットになっています。

```css
--text-quiz-p-answer: 96px;
--text-quiz-p-answer--line-height: 97px;
--text-quiz-p-answer--font-weight: 900;
```

この3行が、**`text-quiz-p-answer` という1つのクラスにまとまります。**

```tsx
{/* ❌ 太さを別に指定しなくていい */}
<p className="text-quiz-p-answer font-black">正解</p>

{/* ✅ これだけで 96px / 行間97px / weight900 が当たる */}
<p className="text-quiz-p-answer">正解</p>
```

`font-bold` を重ねると、**トークンが持っている太さを上書きしてしまいます。** Figma と食い違う原因になるので、重ねないでください。

### 書体

`index.css` の `@theme` には名前が定義されていますが、**フォントファイルはまだ読み込んでいません。** 現時点では指定しても端末標準で表示されます。

これは意図的です（→ §5）。

## 2. どのトークンを使えばいいか

**Figma のスタイル名が、そのままクラス名になっています。**

Figma でテキストを選んで、右パネルに出ているスタイル名を見てください。

```
Figma のスタイル名          →   Tailwind のクラス
quiz/header                     text-quiz-header
quiz/p/answer                   text-quiz-p-answer
quiz/admin/list-label           text-quiz-admin-list-label
```

`/` が `-` になるだけです。**自分で選ぶ必要はありません。Figma を見て、その名前を書いてください。**

### 画面ごとの接頭辞

| 接頭辞 | 画面 | 例 |
| --- | --- | --- |
| `quiz-` | **スマホ**（#18） | `text-quiz-question-body` |
| `quiz-p-` | **モニタ**（#19） | `text-quiz-p-question-body` |
| `quiz-admin-` | **管理**（#20） | `text-quiz-admin-header` |

`p-` はモニタ（Presentation）です。**モニタは遠くから見るので、スマホとは別のスケールになっています。** `text-quiz-p-answer` は 96px、スマホの `text-quiz-correct-body` は 28px です。

**自分の画面の接頭辞のものだけを使ってください。** モニタ用のトークンをスマホで使うと、文字が画面からはみ出します。

---

## 3. 余白（spacing）は別の仕組みです

余白は `@theme` ではなく、**Figma の Variables** で管理しています（#54）。Tailwind 側は既定のスケールをそのまま使います。

```
Figma の px ÷ 4 = Tailwind の数字
```

| Figma | Tailwind |
| --- | --- |
| 16px | `p-4` `gap-4` |
| 24px | `p-6` |
| 10px | `p-2.5` |
| 40px | `p-10` |

詳細は [`Figma・Tailwindスペーシング対応表.md`](./Figma・Tailwindスペーシング対応表.md) を見てください。

### 表に無い余白が出てきたら

`13px` `17px` `19px` `23px` `29px` `33px` は、**意図的にスケールから外した値**です（#54 の決定）。丸めないでください。

```tsx
{/* この6つの値だけは任意値で書いてよい */}
<div className="py-[13px] pr-[29px]">
```

**それ以外の値で任意値を書きたくなったら、まず Figma を確認してください。** ほとんどの場合、Figma 側の値がずれているだけです。

## 4. やってはいけないこと

| ❌ | なぜ |
| --- | --- |
| `text-[#192085]` | 色が確定したときに置換漏れが出る |
| `text-[20px]` | 行間と太さが抜ける。Figma と一致しなくなる |
| `text-cyan-500` など Tailwind の既定色 | このアプリのパレットではない |
| `text-quiz-header font-bold` | トークンの太さを上書きしてしまう |
| モニタ用トークンをスマホで使う | 96px が出てレイアウトが壊れる |
| `index.css` を手で編集する | 次の生成で消える（→ §6） |

**「トークンに無いから直書きする」は、ほぼ間違いです。** 無いということは Figma にもその指定が無い、ということなので、まず Figma を見てください。

---

## 5. まだ決まっていないこと

作りながら「これ大丈夫か？」と思ったとき用に、現状を書いておきます。

**色の名前は確定ですが、値は暫定です。** `--color-brand: #192085` が「パンフ・HPの青」かどうかは未確認です。**名前で参照している限り、値が変わっても実装は直す必要がありません。**

**書体は未定です。** `Zen Kaku Gothic New` が `@theme` に入っていますが、フォントファイルは読み込んでいません。

読み込んでいない理由は、**日本語の Web フォントが1書体で数MBあるから**です。本番は会場で 200人が同時にアクセスします。問題が表示される前に読み込みが終わらない可能性があるので、配信方法（サブセット化するか、端末標準にするか）を決めてからにします。

**この判断待ちで実装を止める必要はありません。** 書体が決まっても、変わるのは `index.css` の1行だけです。

---

## 6. トークンを更新する流れ

**`index.css` は手で書きません。** Figma のスタイルから機械的に生成しています。

```
Figma でスタイルを直す
        ↓
プラグインを実行して @theme を出力
        ↓
index.css に貼り替える
```

| 対象 | プラグイン |
| --- | --- |
| 色 | [`figma-plugin/color-styles-export/`](../figma-plugin/color-styles-export/) |
| 文字・書体 | [`figma-plugin/text-styles-export/`](../figma-plugin/text-styles-export/) |

手で書いた対応表を持たないのは、**必ず腐るから**です。Figma の名前がそのままクラス名になっているので、対応表そのものが不要になっています。

**トークンを増やしたいときは、Figma でスタイルを作ってください。** `index.css` に直接足すと、次の生成で消えます。

## 7. 困ったら

| 症状 | 見るところ |
| --- | --- |
| クラスを書いたのに効かない | `index.css` にその変数があるか。名前のタイプミス |
| 文字サイズは合うが太さが違う | `font-bold` などを重ねていないか |
| Figma と余白が合わない | px ÷ 4 の対応表（§3） |
| 使いたいスタイルがトークンに無い | Figma 側にスタイルが当たっていない可能性。PM に相談 |

わからなければ PM に聞いてください。**自己判断で直書きするより、聞いたほうが早いです。**
