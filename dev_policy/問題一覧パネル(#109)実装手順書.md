## 3. 設計方針

### 3-1. `QuestionList` は「表示するだけ」の部品にする

**受け入れ条件に明記されている制約:**

> `QuestionList` が `props` だけで描画でき、通信に依存していない

`fetch` も `localStorage` もこのファイルの中に書かない。通信は `OperationPanel.tsx` に寄せる(#20 手順書 §5 と同じ原則)。

```tsx
// parts/QuestionList.tsx のイメージ
type Props = {
  items: QuestionListItem[]
  selectedId: number | null
  onSelect: (id: number) => void
  // 今モニタに出ている問題。選択中(まだ出題していない)とは別物なので分けて受け取る。
  // #108 が無い現時点では常に state.question?.id を渡す想定(§5)
  currentQuestionId: number | null
}
```

`disabled` のような「出題中は操作を止める」props は **#108 が無い今は作らない。** 必要になるのは出題ボタンができてから(§1 のスコープ外)。今作ると使われない props になる。

### 3-2. 列は Figma 準拠 + Issue が指定する2列を追加

| 列 | 元になる値 | Figma にあるか |
| --- | --- | --- |
| 選択(ラジオ) | 単一選択 | ○ |
| ID | `id` | ○ |
| 問題文 | `textPreview` | ○ |
| 形式 | `type` → `questionTypeLabel()` | ○ |
| 難易度 | `difficulty` → `difficultyLabel()` | ○ |
| 出題済み | `asked` | **✕(Issue が明示的に追加を指示)** |
| 画像あり | `hasImage` | **✕(Issue が明示的に追加を指示)** |

⚠️ **Figma の列は「ID」であって「番号」ではない。** `number` フィールドは `CurrentStatus`(第◯問表示)で使うものなので混同しないこと(§4 Step 1 の参考コードがまさにこれを間違えている例なので、そこで直し方を示す)。

### 3-3. バッジの方針

デザインが未確定なため、**`StatusBadge.tsx` と見た目を揃えた新しいバッジを先に実装してよい**(Issue 本文の指示)。`StatusBadge` 自体は `AdminStatus`(`accepting`/`closed`/`answer`)専用の型なので、これを流用せず、同じトーンで新規に作る。

- 形式・難易度・出題済み・画像あり、**4種類とも同じ見た目のバッジ部品**にする(ばらばらの装飾にしない)
- 色は既存の Tailwind トークン(`text-admin-func-label` など)を使い回す。新しい色を増やさない
- 出題済み(`asked: true`)の行は **行ごと薄く(`opacity-60` など)** して視認性を上げる(§4「出題済みの問題が分かるようにする」の実装例と同じ考え方)

### 3-4. 0件表示

```tsx
if (items.length === 0) {
  return <p>問題がありません。</p>
}
```

**テーブルの外枠ごと出し分ける。** 空の `<table>` を描画して中身だけ空、という実装にすると「壊れているのか0件なのか」が裏方に伝わらない。

### Step 1: `QuestionList.tsx` を作る

ゼロから書く前に、`feat/20-admin-page` ブランチ(PR #99 のフォークポイント)にある同名ファイルの試作を読む。**参考コード**(`git show feat/20-admin-page:frontend/src/features/admin/parts/QuestionList.tsx` の中身そのまま):

                  name="question"
                  value={item.id}
                  checked={selectedId === item.id}
                  disabled={disabled}
                  onChange={() => onSelect(item.id)}
                />
                選ぶ
              </label>
            </td>
            <td>{item.number}</td>
            <td>{questionTypeLabel(item.type)}</td>
            <td>{difficultyLabel(item.difficulty)}</td>

**このまま使えない。書く前に次の3点を直す:**

1. ⚠️ **`番号`列(`item.number`)になっている → `ID`列(`item.id`)に直す。** Issue 本文・`docs/実装要件/画面・要件.md` が指す列は `id` であって `number` ではない(`number` は `CurrentStatus.tsx` の「第◯問」表示用)。列見出しも値も入れ替える
2. ⚠️ **`disabled` props がある → 今回は作らない。** 「出題中はボタンを無効化する」ための props だが、それを呼び出す #108(出題フォーム)がまだ無いので値を渡す先が無い。残すと使われない props になるので削る
3. ⚠️ **画像・状態を素の文字列(`あり`/`出題済み`)で出している → §3-3 のバッジ方式に置き換える。** デザイン未確定なので `StatusBadge.tsx` と同じトーン(角丸ピル)の新規バッジ部品にする。文字列のまま出さない

3点を反映すると、`frontend/src/features/admin/parts/QuestionList.tsx` は次の形になる:

```tsx
import type { QuestionListItem } from '../../../types'
import { difficultyLabel, questionTypeLabel } from '../labels'

type Props = {
  items: QuestionListItem[]
  selectedId: number | null
  onSelect: (id: number) => void
  // 今モニタに出ている問題。選択中(まだ出題していない)とは別物なので分けて受け取る
  currentQuestionId: number | null
}

// 問題一覧。ここから1問選び、(#108 の出題フォームで)出題する。
// 「次へ」ではなく「この問題を出す」と指定する方式なので、二度押ししても事故らない
export function QuestionList({ items, selectedId, onSelect, currentQuestionId }: Props) {
  if (items.length === 0) {
    return <p>問題がありません。</p>
  }

  return (
    <table>
      <thead>
        <tr>
          <th></th>
          <th>ID</th>
          <th>問題文</th>
          <th>形式</th>
          <th>難易度</th>
          <th>出題済み</th>
          <th>画像</th>
        </tr>
      </thead>
      <tbody>
        {items.map((item) => (
          <tr
            key={item.id}
            // 出題済みは薄くする。当日「もう出した問題」を潰しながら進めるため
            className={item.asked ? 'opacity-60' : undefined}
          >
            <td>
              <label>
                <input
                  type="radio"
                  name="question"
                  value={item.id}
                  checked={selectedId === item.id}
                  onChange={() => onSelect(item.id)}
                />
                選ぶ
              </label>
            </td>
            <td>{item.id}</td>
            <td>{item.textPreview}</td>
            <td>
              <Badge>{questionTypeLabel(item.type)}</Badge>
            </td>
            <td>
              <Badge>{difficultyLabel(item.difficulty)}</Badge>
            </td>
            <td>
              {/* 今出ている問題は、出題済みより先に表示する(裏方が探すのはまずこれ) */}
              {item.id === currentQuestionId ? (
                <Badge>表示中</Badge>
              ) : (
                item.asked && <Badge>出題済み</Badge>
              )}
            </td>
            <td>{item.hasImage && <Badge>画像あり</Badge>}</td>
          </tr>
        ))}
      </tbody>
    </table>
  )
}

// StatusBadge.tsx と同じトーン(角丸ピル)の汎用バッジ。
// StatusBadge は AdminStatus 専用の型なので流用せず、見た目だけ揃えて別部品にする
function Badge({ children }: { children: React.ReactNode }) {
  return (
    <span className="rounded-full bg-surface-soft px-3 py-1 text-admin-func-label whitespace-nowrap">
      {children}
    </span>
  )
}
```

### Step 4: `OperationPanel.tsx` に配線する

ここが唯一「通信」が絡む場所。`useState` + `useEffect` で一度だけ `getQuestions()` を呼ぶ。

```tsx
import { useEffect, useState } from 'react'
import { ApiError, getQuestions } from '../../lib/api'
import { toMessage, NETWORK_ERROR_MESSAGE } from './errorMessages'
import { QuestionList } from './parts/QuestionList'
import type { QuestionListItem } from '../../types'

export function OperationPanel({ onAuthExpired }: Props) {
  const state = useAdminState(onAuthExpired)
  const deadlinePassed = useDeadlinePassed(state)

  const [questions, setQuestions] = useState<QuestionListItem[] | null>(null)
  const [questionListError, setQuestionListError] = useState<string | null>(null)
  const [selectedId, setSelectedId] = useState<number | null>(null)

  useEffect(() => {
    let cancelled = false
    getQuestions()
      .then(({ questions }) => {
        if (!cancelled) setQuestions(questions)
      })
      .catch((e) => {
        if (cancelled) return
        if (e instanceof ApiError && e.status === 401) {
          onAuthExpired()
          return
        }
        setQuestionListError(e instanceof ApiError ? toMessage(e.code) : NETWORK_ERROR_MESSAGE)
      })
    return () => {
      cancelled = true
    }
  }, [])

  if (state === null) return <p>接続中...</p>

  return (
    <div>
      <CurrentStatus state={state} status={toStatus(state, deadlinePassed)} />
      {questionListError !== null && <p>{questionListError}</p>}
      {questions !== null && (
        <QuestionList
          items={questions}
          selectedId={selectedId}
          onSelect={setSelectedId}
          currentQuestionId={state.question?.id ?? null}
        />
      )}
    </div>
  )
}
```

ポイント:

- **`questions === null` の間は一覧を出さない**(取得前と0件を区別する)。ローディング中は `<p>問題一覧を取得中...</p>` のような表示を足してよい
- **401 は `onAuthExpired()` に流す。** 他の画面と同じく「どのAPIでも401ならログイン画面に戻す」(フロントエンド実装要件.md §4)を守る
- **`message` を直接出さない。** `ApiError` なら `toMessage(e.code)`、そうでなければ `NETWORK_ERROR_MESSAGE`(#20 手順書 §7 と同じ分岐)
- `currentQuestionId` は `state.question?.id ?? null` で **毎回 `AdminState` から導出する。** 別に状態を持たない(フロントで独自に集計しないのと同じ理由)
- **一覧の再取得は今回やらない。** `showQuestion()` が無い(#108未実装)ため、取得後に `asked` が変わる経路が存在しない。#108 実装時に「出題成功後に再取得する」を足す想定(TODOコメントは不要、コードが無いので今は再取得のしようがない)

## 7. 落とし穴

### 7-1. 難易度・形式は日本語で表示する

API は `easy`/`normal`/`hard`、`four_choice`/`two_choice`/`arunashi` を返す。**画面では日本語に引き直す。** `labels.ts` の `difficultyLabel()` / `questionTypeLabel()` を使う。**同じ日本語表記を2箇所に持たない**(`arunashi` は「有無」で統一。`labels.ts` に無い独自の対応表を作らない)。

### 7-2. 画像は一覧に並べない

`hasImage` は boolean。URL は返ってこない。**`<img>` タグを一覧に置かない。** 数十件の一覧で画像を数十枚読み込む重い画面を避けるための設計(API仕様書 §4.1)。バッジで「画像あり」が分かればよい。

### 7-3. 仮データの扱い(最重要)

**`GET /api/admin/questions` は #98 でマージ済み。** 404 フォールバックで仮データを出す実装は**持ってこない。** 本番APIが落ちたときに架空のクイズが画面に出てしまう事故を防ぐため。

- `/dev/admin` のプレビューに並べる架空データだけを `__devPreviewData.ts` に置く
- これは `props` に直接渡すもので、**通信の失敗時に出てくるものではない**
- 通信が失敗したときは §4 の `questionListError` のように**エラーメッセージだけ**を出す

🔒 **本番の問題文・正答を書かないこと。** このリポジトリは公開されている。架空の問題だけを使う。

### 7-4. `features/` 間の import 禁止

`features/monitor/` `features/phone/` から import しない(#20 手順書 §3 と同じ理由)。バッジの見た目を揃える指示は「同じコードを共有する」ことではなく「同じトーンで新規に書く」こと。

### 7-5. 🚫 `dangerouslySetInnerHTML` 禁止

`textPreview` はサーバー由来の文字列。通常の JSX(`{item.textPreview}`)で表示すれば React が自動エスケープする。localStorage にトークンを持つ画面なので、ここが XSS 経路になると被害が大きい。

### 7-6. 🚫 トークンを console.log に出さない

このイシューではトークンを直接扱わないが、`getQuestions()` の呼び出し・エラー処理を書く過程で `console.log(e)` のようなデバッグコードを残さないこと。残すなら `e.code` や `e.status` に留める。
