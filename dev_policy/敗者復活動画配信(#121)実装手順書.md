# 敗者復活動画配信(#121) 実装手順書 — codex 向け

Issue #121 の実装をコード生成エージェント(codex)にやらせるための手順書。
**この手順書どおりにコミットを3つに分けること。** 1コミット1ファイル種別(backend / frontend-infra / compose)にして、レビューで「どこが何を触ったか」が diff だけで分かるようにする。

このリポジトリは squash merge なので `main` にはこの3コミットは残らないが、**PRを作る前の途中経過(Draft PR)を見るレビュワーのために分ける**。1コミットずつ `git diff` が追える状態にすること。

前提: ブランチは `feat/121-videos-static` で作業中(すでに切ってある)。**新しいブランチは作らない。**

> **2026-09-18 / Issue #158で投入方法を変更:** #121時点では「動画はCTへscpで直接置く」と決めていた。しかし、Q6の「CTへのSSH経路が無い」が未解決のままであり、CDを含む「当日運営はCT・サーバーに一切触らない」方針とも矛盾していた。このため、現在は管理者画面から専用API `POST /api/admin/videos` へ送り、`backend/static/videos/revival.mp4` を同名上書きする。#121で作った `GET /videos/...` の配信経路はそのまま使う。

## コミット2: frontend/infra — nginx に `/videos/` を中継させる

### 触るファイル
- `frontend/nginx.conf`

### 変更内容

`location /images/` ブロックのすぐ後ろに、同じ形で `location /videos/` を追加する。**中身は流用するが、以下の3点だけ画像と変えない/変える判断をすでにしている(Issue本文の「⚠️ nginx側の注意」を守ること):**

- `client_max_body_size` は触らない(このブロックの外の話なので何もしなくてよい)
- キャッシュは画像と同じ `max-age=300` に揃える(画像と同じ「ファイル名を変えずに差し替える」運用のため)
- `proxy_buffering off` は入れない(SSE専用設定。動画の `Range` リクエストは素通しで効くので不要)

```nginx
    # ---- 敗者復活の動画 ----------------------------------------
    # backend の r.Static("/videos", "./static/videos") へ中継する。
    # /images/ と同じ理由(SPAフォールバックより先に選ばれる必要がある)で
    # location / とは別に切る。投入はPOST /api/admin/videosから行う(#158)。
    location /videos/ {
        resolver 127.0.0.11 valid=10s;
        set $backend_upstream "http://backend:3000";
        proxy_pass $backend_upstream;

        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 画像と同じ運用(ファイル名を変えずに差し替える)にするため、キャッシュも揃える。
        add_header Cache-Control "public, max-age=300";

        # ★ /images/ と同じ理由でMIMEスニッフィングを禁止する。
        add_header X-Content-Type-Options "nosniff";

        # ★ proxy_buffering off はここに入れない。/api/ のSSE専用設定であり、
        #   動画の Range リクエストは素通しのままで正しく効く。
    }
```

### このコミットでのセルフチェック

nginx設定の構文だけでよい(本番構成の起動確認はコミット3の後にまとめて行う)。


## コミット3: infra — 本番構成の動画置き場を明記する

### 触るファイル
- `docker-compose.prod.yml`

### 変更内容

`backend.volumes` の `./backend/static:/app/static` は**画像と動画の両方をすでにカバーしている**(ディレクトリ丸ごとのマウントのため)。新しいマウント行は追加しない — 追加すると同じパスを二重にマウントすることになり、事故のもと。

**やることはコメントの更新のみ。** 動画もこのマウント1行で配信されることを明記する。

```yaml
    volumes:
      # 問題の画像と、敗者復活の動画(#121)。どちらもここから配信される
      # (backend/internal/platform/router.go の r.Static("/images", ...) / r.Static("/videos", ...))。
      #
      # ★ イメージに焼かずボリュームで渡す。COPY にすると1枚足すたびに
      #   backend の再ビルドが要るうえ、up --build のたびに手で置いた分が消える。
      #   画像・動画の投入APIも、このマウント先へ保存する。
      #   動画は backend/static/videos/revival.mp4 の固定名で上書きする(#158)。
      - ./backend/static:/app/static
```

## PRを作るとき

- コミット・push前に `git status` でダミー動画(`backend/static/videos/test.mp4` 等)が紛れていないか必ず確認する
- タイトル例: `敗者復活の動画配信経路 /videos/ を作る (#121)`
- `closes #121` を本文に入れる
- **検証結果は `curl -sI` の出力だけを貼る。** `docker compose config` や `env` の出力は絶対に貼らない(トークンが写る — Issue本文の警告)
- `mise run lint` が通ることを確認してから Ready にする
