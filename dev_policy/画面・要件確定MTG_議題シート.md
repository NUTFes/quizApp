# 画面・要件確定ミーティング 議題シート(改訂版)

> 2026-07-20 改訂: ゲーム形式は**確定済み**(勝ち残り×移動形式・回答機能なし・順次表示)と判明したため、
> 旧G1/G2は「確定事項の共有」に変わり、議題は残りのN項目+数値ものに絞られた。
> 使い方: 第0部で認識合わせ → 第1部で残り5点を決める → 第2部で数値を埋める。目標30分。

## 第0部: 確定事項の共有(議論しない。認識ずれがないかだけ確認)

- ゲーム形式: **勝ち残り × 移動形式**。会場を**2×2の4エリア**に分割し、各エリア=選択肢。参加者は選んだエリアへ移動して回答
- **アプリに回答機能はない**。回答の判定・脱落管理は運営の人力
- 早押しの自動判定はしない。早押し風の問題は「**MCの読み上げに合わせて問題文を順々に表示**」する演出で代替
- アプリの役割 = モニタ表示(問題・2×2選択肢・正答)+管理者の進行操作

## 第1部: 残りの要決定(N1〜N5)

| # | 議題 | 推奨案 | 決定 |
|---|---|---|---|
| N1 | 参加者スマホ用の表示ページ(見るだけのミラー)を作るか | ✅ **決定済み: 作る**(会場規模的にモニタだけでは見えないため)。QR掲示・想定人数の確定・負荷試験がタスクに復活 | ✅作る |
| N2 | 問題文の順次表示のやり方 | **案1: 自動タイプライター**(出題ボタンで文字が一定速度で流れ、MCが表示に合わせて読む)/ 案2: 手動送り(MCの読みに合わせて管理者がボタンで1区切りずつ出す)。**MCの読みやすさで選んでもらう** | |
| N3 | 移動締切タイマーをモニタに出すか | 出す。締切秒数のデフォルト値: ____ 秒(問題ごとにスプシで上書き可) | |
| N4 | (N2が案2のとき)問題文の区切り記法 | スプシのtext列に `/` を入れる | |
| N5 | 問題形式ごとのエリア対応 | 4択=4エリア全部 / 2択・○×=どの2エリアを使う?(左右2エリア推奨: 「左半分がA、右半分がB」が一番口頭で説明しやすい) | |

## 今日決めないこと(脱線防止)

- デザイン詳細(色・フォント・余白) → ワイヤー確定後
